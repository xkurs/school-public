Вывод и фильтрация каталога по данным массива

Продолжаем VariantNN-web. На паре 21 вы собрали массив catalog, на паре 22 — функцию filterByText, на паре 23 научились находить элементы страницы, создавать новые блоки и обрабатывать события. Сегодня каталог перестанет быть статической разметкой: карточки будет строить программа, а поле поиска — отбирать нужные записи.

Результат: в catalog.html три карточки выводятся из массива, работают поиск по названию и счётчик «Показано: N из 3», при пустом результате появляется «Ничего не найдено». Меню, переходы и оформление карточек сохраняются.

Рабочий ритм: изменить → сохранить → обновить страницу → проверить.

1. Проверьте исходные данные

Откройте свою папку и catalog.js. В нём должны остаться массив catalog из трёх объектов с полями position, name, specs, description и функция filterByText из пары 22. На главной странице подключён именно catalog.js.

В консоли (F12 → Console / Консоль) проверьте:

JavaScript
console.log(catalog.length);
console.log(filterByText(catalog, "").length);

Оба числа совпадают с числом ваших карточек; в проекте их три. Если filterByText не найдена, восстановите её по паре 22; без неё поиск на этой паре не собрать. Затем откройте catalog.html: в нём пока три готовых article. Их тексты должны совпадать с объектами массива. Если расходятся, сначала сверьте их: после замены разметки данные станут единственным источником карточек.

2. Замените карточки контейнером и добавьте поиск

Файл: catalog.html, внутри main, вместо трёх article. Если они были обёрнуты в <div class="products">, заменяйте весь этот блок, а не вставляйте новый контейнер внутрь него.

HTML
<p>
  <label for="search">Поиск по названию</label>
  <input id="search" type="search" placeholder="Введите часть названия">
</p>
<div id="catalog-list" class="products"></div>
<p id="status" role="status"></p>

label for="search" связывает подпись с полем, у которого id="search": щелчок по подписи ставит курсор в поле. type="search" даёт браузеру подсказку, что это поиск. Контейнер с id="catalog-list" остаётся пустым — его заполнит программа. Класс products сохраняет прежний ряд карточек из пары 18; если ваши карточки оформлены иначе, используйте свой класс или уберите его. role="status" сообщает браузеру и программам чтения с экрана, что текст обновляется программно; пока абзац пуст.

Проверьте: откройте каталог. Три прежние карточки исчезли, появились подпись, поле поиска и пустое место под них. Тексты карточек не потеряны: они остались в массиве.

3. Создайте отдельный файл для страницы каталога

Рядом с catalog.html создайте catalog-page.js. Перенесите в него из catalog.js массив catalog и функцию filterByText. Старый catalog.js не удаляйте: на главной он продолжает работать с расчётом и опытами пары 22.

JavaScript
const catalog = [
  // три ваших объекта из catalog.js
];

Подключите новый файл в catalog.html перед закрывающим </body>:

HTML
<script src="catalog-page.js" defer></script>

defer разрешает браузеру сначала разобрать HTML, а затем выполнить программу. Поэтому к моменту поиска элементов контейнер и поле уже существуют. Скрипт стоит в конце body; если перенести его в head без defer, поиск элементов может выполниться раньше разметки.

Проверьте: обновите каталог, откройте консоль. catalog.length даёт 3, filterByText(catalog, "").length — тоже 3. Ошибок нет.

4. Соберите карточки функцией

Сначала найдите элементы страницы и подготовьте функцию. Пишите после массива и filterByText.

JavaScript
const catalogList = document.querySelector("#catalog-list");
const statusText = document.querySelector("#status");

function renderCatalog(items) {
  catalogList.replaceChildren();
  for (const item of items) {
    const card = document.createElement("article");
    card.className = "card";
    const title = document.createElement("h2");
    title.textContent = item.name;
    const specs = document.createElement("p");
    specs.textContent = item.specs;
    // 1. Создайте description и заполните его item.description.
    // 2. Соберите card и добавьте её в catalogList.
  }
}

replaceChildren() без аргументов очищает контейнер перед новым выводом. Без очистки каждый вызов добавлял бы ещё три карточки к уже существующим.

Вместо двух комментариев допишите:

JavaScript
const description = document.createElement("p");
description.textContent = item.description;
card.append(title, specs, description);
catalogList.append(card);

append принимает несколько элементов сразу и вставляет их по порядку. Класс card в примере — тот же, что у прежних карточек; если у ваших article другой класс, подставьте своё имя, иначе оформление не применится.

В конце функции, после цикла, добавьте счётчик:

JavaScript
if (items.length === 0) {
  statusText.textContent = "Ничего не найдено";
} else {
  statusText.textContent = "Показано: " + items.length + " из " + catalog.length;
}

Число 3 здесь не записано вручную: catalog.length берётся из массива, поэтому подпись останется верной и при другом количестве карточек. При пустом результате вместо «Показано: 0 из 3» выводится «Ничего не найдено»: так понятно, что записей нет, а не что сломался счётчик.

Вызовите функцию после её закрывающей скобки: renderCatalog(catalog);. На странице должны появиться три карточки с заголовком, характеристикой и описанием, под ними «Показано: 3 из 3». В консоли ошибок нет.

В массиве пока нет адреса изображения, поэтому карточки выводятся без картинок. Это не ошибка: тексты сохранены, файлы лежат в images/, а для вывода изображений понадобится новое свойство в данных.

5. Почему textContent, а не innerHTML

textContent записывает в элемент именно текст. Если в названии карточки встретятся символы <b> или &, они останутся видимыми символами и не станут разметкой.

innerHTML разбирает строку как HTML. Данные при этом превращаются в разметку: случайная угловая скобка ломает карточку, а посторонний текст может добавить ссылку или другой элемент. Данные должны оставаться данными, поэтому название, характеристика и описание заполняются через textContent, а элементы создаются через createElement.

Проверьте: временно замените название первой карточки на <b>Проверка</b>, сохраните и обновите страницу. Символы <b> видны как текст, жирного начертания нет. Верните настоящее название и не исправляйте это через innerHTML.

6. Свяжите поле поиска с фильтром

Добавьте после вызова renderCatalog(catalog);:

JavaScript
const searchInput = document.querySelector("#search");

searchInput.addEventListener("input", function () {
  const found = filterByText(catalog, searchInput.value);
  renderCatalog(found);
});

Событие input наступает при каждом изменении поля: при наборе, вставке и очистке. Обработчик получает текущий текст, передаёт его в filterByText вместе с массивом и выводит найденное.

Функция пары 22 приводит запрос к нижнему регистру, убирает пробелы по краям и отбирает записи условием item.name.toLowerCase().includes(normalized). Для непустого запроса filter возвращает новый массив; пустой запрос возвращает весь catalog. В обоих случаях исходный массив не меняется: renderCatalog только читает его.

Поиск идёт только по названию. Характеристика в условие не входит: подпись поля остаётся правдивой, а результат предсказуемым. Если нужно искать и по характеристике, это отдельное изменение — оно описано в разделе «Если закончили раньше».

Проверьте: введите часть названия — остаются подходящие карточки, счётчик уменьшается. Смените регистр — результат тот же. Очистите поле — снова три карточки и «Показано: 3 из 3».

7. Проверьте оформление и переходы

У каждой созданной карточки должен быть тот же класс, что у прежних article. Контейнер #catalog-list с классом products сохраняет ряд и перенос карточек из пары 18; на узком окне карточки по-прежнему идут по одной. В меню каталога остаются переходы на главную и форму: проверьте оба, а также возврат в каталог. Новый скрипт не должен влиять на эти страницы.

Проверьте: сузьте окно до ширины телефона. Карточки не выходят за край, текст читается, оформление рамок и отступов сохранилось.

8. Испытайте поиск

Для вашего количества карточек замените 3 на своё число; ниже — для трёх записей. После каждого опыта возвращайте поле в исходное состояние.

Испытание Что сделать Ожидаемый результат
Полный каталог Не вводить запрос или очистить поле Три карточки, «Показано: 3 из 3»
Часть названия Ввести 2–4 буквы из названия одной карточки Только подходящие записи; число карточек совпадает с числом в статусе
Другой регистр Ввести тот же текст заглавными буквами Результат как в предыдущем опыте
Характеристика не участвует Ввести слово, которое есть в specs, но которого нет ни в одном названии «Ничего не найдено»: поиск идёт только по названию

Покажите результат

  1. Откройте главную, перейдите в каталог по меню. Покажите три карточки и счётчик.
  2. Введите часть названия, затем тот же текст в другом регистре, затем очистите поле.
  3. Введите слово из характеристики, которого нет в названии, и объясните, почему результат пуст.
  4. Откройте элементы страницы (F12 → Elements / Элементы) и покажите, что карточки находятся внутри #catalog-list и имеют ваш класс карточки (card в примере).
  5. Перейдите на форму и вернитесь в каталог.

Объясните, почему для текста выбрано textContent, почему исходный catalog не меняется и где создаётся отобранный массив. Отдельный отчёт не нужен.

Если закончили раньше

Поиск по двум полям. Создайте копию filterByText под именем filterByTextAndSpecs. В её return замените условие на такое:

JavaScript
return items.filter(item =>
  item.name.toLowerCase().includes(normalized) ||
  item.specs.toLowerCase().includes(normalized)
);

Остальные строки функции не меняются. В обработчике замените вызов filterByText на новую функцию, а подпись поля — на «Поиск по названию и характеристике». Проверьте слово, которое есть только в характеристике: теперь карточка находится. Затем проверьте пустой запрос и отсутствие совпадений.

Выделение найденного фрагмента потребует собирать заголовок из нескольких текстовых узлов. Это отдельная задача, не обязательная сегодня.
