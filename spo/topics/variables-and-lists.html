Переменные, списки и данные

Главная мысль: одна переменная удобна для одного значения, а список — для нескольких однотипных значений.

Наш счётчик хранит число выполненных занятий сегодня. Но если нужно помнить результат каждого дня недели, одной переменной count мало. Можно завести список, например [2, 0, 3]: в первый день два занятия, во второй ни одного, в третий три. Новый результат добавляется в конец списка, а итог можно вычислить, пройдя по всем элементам.

Разберите вручную алгоритм: начали с пустого списка; добавили 2, затем 0, затем 3; получили три элемента. Сумма — 5. Спросите, что означает пустой список: «пока нет записей», а не обязательно «все дни по нулю». Это различие пригодится позднее при проектировании интерфейса.

Не спешите вводить много новых блоков. Попросите студентов назвать данные для других простых приложений: список задач, список оценок, каталог книг. Где достаточно одного значения, а где действительно требуется коллекция?

После добавления значений предложите вручную найти максимальный элемент и обсудить данные для собственной идеи приложения.

покажите блок создания списка и добавления значения на подготовленном примере. Если нет — разыграйте работу списка карточками на доске. Главное сейчас — выбор структуры данных, а не скорость щёлканья блоков.

Итог: студент приводит один пример одиночного значения и один пример списка, затем вручную выполняет добавление и подсчёт на трёх элементах.
