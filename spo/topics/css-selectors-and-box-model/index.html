CSS: селекторы, каскад, размеры, отступы и блочная модель

Что получится

Продолжаем три страницы своего приложения: главную, каталог и форму. На этой паре научимся выбирать элементы через CSS, находить причину конфликта правил и управлять размерами блока. Содержание страниц и данные формы сохраняются. Общий style.css получит понятную основу для дальнейшего оформления.

Текущий набор индивидуальных заданий — используйте свой прежний номер и данные. Примеры относятся к учебному варианту 00 «Техника дома»; студентам он не назначается. Названия холодильника, стиральной машины и электрочайника в объяснениях заменяйте своими позициями.

Обязательный минимум одинаков для всех: общий CSS работает на трёх страницах; основная часть каждой имеет класс page, три позиции каталога — класс card; настроены размеры, рамки и отступы; выполнены опыты с каскадом, наследованием и блочной моделью в средствах разработчика. После опытов временные изменения убраны, исходные меню, изображения и форма работают.

Читайте один шаг → меняйте указанный файл → сохраняйте → обновляйте браузер → проверяйте результат. Не ждите промежуточного подтверждения преподавателя. В начале есть короткие образцы; затем тот же приём нужно повторить самостоятельно. Готовую работу показывают один раз в конце. Если минимум выполнен, переходите к продолжению для оценки «отлично».

Этап 1. Проверьте исходный проект

Файлы и место: прежняя папка VariantNN-web, файлы index.html, catalog.html, form.html, style.css и папка images.

Откройте главную в браузере. Пройдите через меню в каталог и форму. Во всех трёх head должно быть одно подключение общего файла:

<link rel="stylesheet" href="style.css">

Самопроверка: в каталоге три полные позиции своего варианта; форма содержит все шесть элементов и кнопку, подписи связаны с полями, пустой обязательный ввод вызывает проверку. Меню горизонтальное и переносится при сужении окна. Если выполняли дополнительные задания, их результаты также сохранены.

Если не получилось: восстановите недостающую часть по статье о главной и каталоге или статье о форме. Новую папку проекта и второй CSS создавать не нужно. Сегодня не переписываем весь HTML ради оформления.

Как читается правило CSS

.card {
  padding: 1rem;
  border: 1px solid #94A3B8;
}

.card — селектор: выбирает элементы с классом card. Между { и } находятся объявления. В объявлении слева от : стоит свойство, справа — значение, в конце — ;. padding задаёт внутренний отступ, border — рамку. CSS не создаёт товар или поле: он оформляет уже существующие элементы HTML.

Запись Что выбирает На нашем проекте
h2 Все элементы с тегом h2 Заголовки позиций и другие h2 на странице
.card Все элементы с классом card Только отмеченные карточки
main.page Элемент main, у которого есть класс page Основная часть страницы
.card p Все абзацы внутри .card, включая вложенные глубже Характеристика и описание позиции
h1, h2 Обе группы элементов Заголовки двух уровней
* Все элементы Общее правило расчёта размеров

Пробел и запятая выполняют разные задачи. .card p ищет абзацы внутри карточки; .card, p выберет и карточки, и все абзацы страницы. main.page без пробела проверяет тег и класс одного элемента; main .page искал бы отдельного потомка main.

В HTML пишут class="card", в CSS — .card. Точка — часть селектора, в значение class она не входит. Класс можно использовать у многих элементов. Если у элемента уже есть класс, допишите второй через пробел: class="old-class card"; второй атрибут class не создавайте.

Этап 2. Отметьте основную часть страниц и карточки

Файл и место: index.html, открывающий тег существующего main.

<main class="page">

Закрывающий тег остаётся </main>. Содержание внутрь нового блока переносить не требуется: вы добавляете атрибут уже существующему элементу.

Самостоятельное повторение: найдите основной main в catalog.html и form.html, добавьте ему тот же класс. Затем в catalog.html отметьте первый товар:

<article class="card">
  <h2>Холодильник</h2>
  <!-- Здесь остаются прежние изображение и абзацы товара -->
</article>

Это фрагмент границ существующей позиции, а не предложение заменить её содержимое комментарием. У второй и третьей позиции добавьте класс самостоятельно. Не присваивайте его всему каталогу: один article — одна карточка.

Самопроверка: в каждой из трёх страниц один основной main с классом page; в каталоге три соседних article с классом card. Данные и переходы прежние. Пока CSS для этих классов нет, внешний вид может не измениться.

Если не получилось: найдите в HTML class=".card", повторный class или второй main, случайно вставленный внутрь первого. Если исчез товар, верните его прежние элементы, изменив только открывающий тег.

Этап 3. Соберите общие правила без дубликатов

Файл и место: style.css. Сначала найдите существующие правила body, main, img, nav и nav a. Сохраните цвета своего варианта, ограничения изображений и всё оформление меню. Правила меню из пары 13 уже используют известный вам способ расположения ссылок; сегодня их не меняем.

Не добавляйте в конец ещё один большой набор с повторениями. Если нужный селектор уже есть, дополните его существующее правило. Если свойство задано дважды, разберитесь, какое значение нужно оставить. Разные селекторы также могут выбирать один элемент: например, старое main и новое main.page.

Добавьте общее правило, если его ещё нет:

* {
  box-sizing: border-box;
}

Затем в существующем body задайте эти свойства; свои color и background-color сохраните:

body {
  font-family: Arial, sans-serif;
  font-size: 1rem;
  line-height: 1.5;
  margin: 0;
}

Образец перечисляет основу, а не весь готовый CSS вашего приложения. font-family задаёт шрифт и запасное семейство, font-size — размер, line-height без единицы — множитель высоты строки. margin: 0 убирает стандартное внешнее поле body; отступы основной части зададим отдельно.

Самопроверка: все страницы открываются, меню сохраняет рамки, перенос и видимый фокус; изображения не выходят за содержимое. Шрифт текста стал общим.

Если не получилось: проверьте закрывающую } предыдущего правила. Объявления не должны находиться вне скобок или внутри другого обычного правила. Если вся страница потеряла цвета, вероятно, вы заменили прежний body целиком и не сохранили его цветовые свойства.

Размеры: px, проценты и rem

Единица От чего зависит Применение здесь
px CSS-пиксель; при масштабировании браузер меняет его отображение Тонкая рамка 1px
% От опорного размера, зависящего от свойства; для обычного width — от ширины содержащего блока Основная часть занимает 92% доступной ширины
rem От вычисленного размера шрифта корневого элемента html Шрифт, отступы и предел ширины

Если корневой размер равен 16px, то 1rem — 16px, 2rem — 32px, а 56rem — 896px. Это пример расчёта, а не гарантия настройки каждого браузера. rem не считается от шрифта самой карточки. В нашем body размер 1rem сохраняет связь с корневым размером.

Проценты не означают всегда «долю экрана»: у карточки внутри main опорным блоком станет main. Значение width: 100% вместе с отступами требует учёта блочной модели.

Этап 4. Ограничьте ширину основной части

Файл и место: style.css, отдельное правило main.page; если оно уже есть, измените существующее.

main.page {
  width: 92%;
  max-width: 56rem;
  margin: 0 auto;
  padding: 1rem;
}

width задаёт ширину, а max-width ограничивает её сверху: в широком окне текст не растягивается бесконечно. margin: 0 auto означает нулевой внешний отступ сверху и снизу и автоматические слева и справа. Для этого обычного блочного элемента с заданной шириной свободное место по бокам делится поровну. padding: 1rem отделяет содержимое от всех четырёх краёв основной части.

Самопроверка: откройте три страницы и измените ширину окна. Основная часть остаётся по центру и на широком окне перестаёт расширяться. Шапка и подвал могут оставаться шире: класс сейчас задан только main. В очень узком окне проверьте, что содержимое доступно и нет случайной горизонтальной прокрутки.

Если не получилось: в HTML должно быть class="page", а в CSS именно main.page. Если ширина не меняется, найдите старую фиксированную ширину или min-width; причину проверим в DevTools. Не уменьшайте шрифт ради того, чтобы спрятать переполнение.

Блок состоит из четырёх областей

Это учебная схема, размеры условны. Содержимое — текст и изображения. Padding лежит между содержимым и рамкой. Border — сама рамка. Margin находится снаружи рамки и отделяет блок от соседей. Фон закрашивает содержимое и внутренний отступ; внешний отступ собственным фоном блока не закрашивается.

padding: 1rem;            /* все стороны */
padding: 0.5rem 1rem;     /* верх/низ, затем лево/право */
margin-bottom: 1rem;      /* только снизу */
border: 1px solid #94A3B8; /* толщина, вид, цвет */

У обычных вертикальных блоков некоторые соседние внешние отступы могут схлопываться: они не всегда складываются. Поэтому расстояние между карточками проверяем в браузере; не обещаем сумму всех значений margin. Отступы внутренних h2 и p тоже влияют на вид карточки.

Этап 5. Дайте карточкам рамку и пространство

Файл и место: style.css, правило .card.

.card {
  border: 1px solid #94A3B8;
  padding: 1rem;
  margin-bottom: 1rem;
}

Рамка нейтральная; свои цвета фона и текста сохраняйте. Карточки пока идут сверху вниз. Это основа для следующей пары, где будем согласованно оформлять страницы, карточки и форму.

Самопроверка: обновите catalog.html: у всех трёх позиций одинаковые рамки, отступ внутри рамки и промежуток после неё. Названия, изображения, характеристики и описания прежние. Абзацы главной и поля формы не получили рамки карточек.

Если не получилось: рамка только у одного товара означает, что у остальных нет класса или имя отличается. Одна рамка вокруг всех товаров обычно означает класс у общего контейнера либо неверно закрытые article. Если изображение шире карточки, восстановите прежнее img { max-width: 100%; height: auto; }.

Этап 6. Откройте средства разработчика

Место: каталог в браузере. Нажмите правой кнопкой по заголовку первой позиции → «Просмотреть код» или «Исследовать элемент»; обычно также работает F12. Названия панелей зависят от браузера: ищите «Элементы» / Elements, «Стили» / Styles, «Вычисленные» / Computed.

В дереве HTML выберите сам article.card, а затем вложенный h2. При наведении браузер подсвечивает соответствующий элемент страницы. В панели стилей видны подходящие правила, а в вычисленных свойствах — итоговые значения. Перечёркнутое объявление часто означает, что для этого свойства выбрано другое; предупреждение рядом с ним может указывать на неверную запись.

Изменения в этой панели временные: они действуют в текущей открытой странице и не сохраняют style.css. После обновления загружается сохранённый файл. Полезную найденную правку нужно отдельно внести в редакторе и проверить после обновления.

Самопроверка: выберите .card и найдите свои padding, border, margin-bottom; затем найдите схему блочной модели и размеры. Временно снимите галочку у padding: текст приблизится к рамке. Верните галочку — отступ восстановится.

Если не получилось: если видны стили h2, выберите его родительский article. Если правило отсутствует, проверьте класс, подключение CSS и сохранение файла. Изменение текста в HTML-дереве браузера также не заменяет сохранение исходника.

Этап 7. Увидьте каскад и наследование

CSS может предложить несколько значений одного свойства одному элементу. Браузер выбирает итоговое значение по каскаду. В следующих опытах рассматриваем обычные правила одного нашего файла, без !important, встроенного style и слоёв каскада. В этих условиях сначала сравнивается специфичность селектора; порядок в файле решает при её равенстве. Правило «последнее всегда побеждает» неверно.

Опыт А. Одинаковая специфичность

Файл и место: временно в самом конце style.css добавьте:

.card p { color: #1D4ED8; }
.card p { color: #1E293B; }

Сохраните и обновите каталог. Выберите абзац карточки в DevTools. Его цвет будет из второго правила: селекторы одинаковы, поэтому для color выбирается более позднее объявление. В панели стилей первое значение должно быть перечёркнуто. Поменяйте порядок двух временных правил, предскажите цвет и проверьте.

Опыт Б. Более конкретный селектор

Вместо двух временных строк используйте:

.card p { color: #1D4ED8; }
p { color: #1E293B; }

Абзац внутри карточки остаётся синим, хотя общее правило p ниже. Класс в .card p делает селектор специфичнее, чем один тег. Специфичность не определяется длиной текста: сравниваются категории селектора. В обычных селекторах идентификаторы #... имеют больший вес, затем классы, атрибуты и псевдоклассы, затем теги. Здесь достаточно классов; вводить id ради усиления CSS не нужно. Универсальный * веса не добавляет.

Самопроверка обоих опытов: объясните, какое именно свойство конфликтует и почему выбран его цвет. Другие свойства карточки продолжают действовать: правило не отменяется целиком из-за проигравшего color.

Опыт В. Наследование

Удалите только временные правила опытов А и Б, сохраните CSS и обновите каталог. В DevTools выберите article.card и в его правило временно добавьте color: #1D4ED8. Посмотрите на текст внутри. Затем выберите абзац и найдите унаследованный цвет или его итог в Computed.

color и семейство шрифта обычно наследуются от родителя, если у самого элемента не задано другое применимое значение. Рамка и внутренний отступ так не передаются каждому потомку. Заголовок и абзацы не получают собственных рамок из .card. Если у абзаца уже есть своё правило color, прямое значение будет использоваться вместо унаследованного — независимо от того, насколько конкретным был селектор родителя.

Самопроверка: отличите прямое правило абзаца от значения, полученного через предка. В body найдите источник общего шрифта. Обновите страницу, чтобы убрать временный цвет из DevTools; исходная палитра должна вернуться.

Если не получилось: выберите абзац внутри карточки, не обычный текст главной. Посмотрите, не осталось ли временное правило в файле, нет ли style="..." у элемента. Не добавляйте !important: найдите подходящее правило и причину выбора значения. Если причина неясна, покажите конкретное свойство и два конфликтующих объявления.

Этап 8. Сравните content-box и border-box

При box-sizing: content-box значение width относится к содержимому. При border-box оно включает содержимое, внутренние отступы и рамку. Margin в width не входит в обоих случаях. Значение по умолчанию у многих обычных блоков — content-box; правило * в начале нашей основы явно назначает border-box элементам проекта.

Место опыта: только DevTools, выбранный первый article.card. В подходящем правиле временно задайте:

width: 240px;
padding: 16px;
border: 2px solid #94A3B8;
box-sizing: content-box;

Сначала предскажите ширину до внешних краёв рамки. Здесь она 240 + 16 + 16 + 2 + 2 = 276px. Сравните со схемой размеров в DevTools. Затем измените только box-sizing на border-box. Внешняя ширина рамки станет 240px, а ширина содержимого — 204px. Текст может переноситься иначе, поскольку места внутри стало меньше.

box-sizing не наследуется; селектор * назначает его каждому выбранному элементу напрямую. В опыте правило .card или временный стиль выбранного элемента переопределяет универсальное правило. На следующей паре не потребуется прибавлять рамку и padding к заданной ширине вручную.

Самостоятельное повторение: в DevTools измените внутренний отступ с 16px на 24px, оставив border-box. Предскажите, что изменится: внешняя ширина рамки или место для текста? Проверьте по схеме, затем обновите страницу. Временные фиксированные 240px в исходный CSS переносить не нужно.

Самопроверка: после обновления карточка снова занимает доступную ширину, а общее box-sizing: border-box действует. В файле остались базовые .card и main.page, нет опытных цветов и ширины 240px.

Если не получилось: различайте размер содержимого в центре схемы и ширину всего блока до края рамки. Не включайте margin в сумму рамки. Если изменение исчезает сразу после обновления, это ожидаемо для DevTools; если остаётся — проверьте, не записали ли вы опыт в файл.

Когда результат отличается от ожидаемого

Исправляйте одну причину, сохраняйте файл и повторяйте соответствующую проверку.

Признак Что проверить
CSS не действует ни на одной странице href, имя и расположение style.css, сохранение, скобки
Одна страница отличается Подключение того же файла и наличие class="page"
Свойство перечёркнуто Другие подходящие объявления этого свойства и их специфичность
