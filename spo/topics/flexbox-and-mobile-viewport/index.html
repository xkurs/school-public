Flexbox, viewport и адаптивный интерфейс мобильной страницы

Что получится

На третьей паре работаем без компьютеров: изучаем Flexbox и viewport, читаем HTML и CSS, рисуем расположение карточек и исправляем код на бумаге. Результат — индивидуальный подписанный лист с ответами и объяснениями. Запуск браузера, изменение файлов и демонстрация проекта на этой паре не требуются.

После двух практических пар у вас уже есть три связанные страницы своего приложения, оформленные карточки и форма. Сегодня выясним, как карточки могут делить строку и переноситься при уменьшении доступного места. Внедрение и проверка этой раскладки на компьютере продолжатся на паре 18.

Текущий набор индивидуальных заданий остаётся прежним. В объяснении используем отдельный пример 00 «Техника дома»: холодильник, стиральная машина, электрочайник. В самостоятельной работе карточки обозначены А, Б и В: результат не зависит от тематики варианта.

Одна оценка по итогу дня

Выполненный и проверенный обязательный результат пар 15–16 даёт «хорошо». Для «отлично» дополнительно выполните бумажную самостоятельную работу этой пары на 9–10 баллов из 10, набрав не менее одного балла в каждом из четырёх блоков.

Без обязательного практического результата первых двух пар бумажная работа сама по себе не даёт «отлично». Дополнительные задания пар 15–16 остаются необязательной тренировкой.

Сначала прочитайте объяснения и разберите учебный пример. Затем выполните четыре блока самостоятельно. Для ответов достаточно бумаги и ручки; задания и код можно переписать на доску или заранее распечатать. Телефон, проектор и компьютер преподавателя не являются условием проведения.

Контейнер управляет непосредственными детьми

Обычные блочные карточки пока идут сверху вниз. Flexbox — способ расположить элементы вдоль выбранной оси и распределить между ними доступное место. Его включают у родителя тех элементов, которые нужно расположить вместе.

main.page
├── h1                        заголовок страницы
├── p                         пояснение
└── div.catalog-list          родитель карточек
    ├── article.card          карточка 1
    │   ├── h2                содержимое карточки
    │   ├── img
    │   └── p ...
    ├── article.card          карточка 2
    └── article.card          карточка 3

Если у .catalog-list стоит display: flex, flex-контейнером становится этот div, а flex-элементами — три его непосредственных ребёнка article. Вложенные h2, img и p не становятся flex-элементами внешнего контейнера: они находятся глубже.

.catalog-list {
  display: flex;
  gap: 1rem;
}

Это правило не заставляет весь текст карточки выстроиться рядом с картинкой. Если назначить display: flex самой .card, оно начнёт управлять её собственными детьми. Если назначить его main, оно будет управлять заголовком, пояснением и общей оболочкой каталога. Поэтому сначала находят нужного родителя в HTML, затем пишут CSS.

gap задаёт промежуток между flex-элементами и строками. Он не создаёт внешний отступ от края контейнера. От края содержимое отделяет padding, а margin находится снаружи рамки элемента.

Главная и поперечная оси

Flexbox располагает элементы вдоль главной оси. Направление этой оси задаёт flex-direction; поперечная ось проходит поперёк неё.

Для обычного горизонтального русского текста:

Направление Главная ось Поперечная ось
row Слева направо Сверху вниз
column Сверху вниз Слева направо

row — исходное значение. column меняет направление раскладки, сохраняя порядок элементов HTML. Первая карточка остаётся первой. Оси можно показать двумя стрелками на бумаге; названия свойств не нужно связывать только со словами «горизонталь» и «вертикаль».

Распределение и выравнивание

justify-content распределяет свободное место вдоль главной оси. align-items выравнивает элементы по поперечной оси в каждой flex-строке.

Свойство Значение Результат при наличии нужного пространства
justify-content flex-start Элементы у начала главной оси
justify-content center Группа элементов в центре главной оси
justify-content space-between Свободное место добавлено между элементами
align-items flex-start Элементы у начала поперечной оси
align-items center Элементы в центре поперечной оси
align-items stretch Элементы с автоматическим поперечным размером растянуты в пределах своей строки

При row свойство justify-content: center располагает группу по горизонтали, а при column — по вертикали. Для заметного эффекта нужно свободное место по соответствующей оси. Если карточки заняли всю строку за счёт роста, распределять остаток уже нечего.

gap и space-between выполняют разные задачи: первый задаёт промежуток, второй распределяет оставшийся избыток. stretch может выровнять высоту рамок карточек одной строки при row, но не делает строки текста внутри карточек одинаковыми и не выравнивает высоты всех строк каталога.

Перенос и гибкие размеры

По умолчанию действует flex-wrap: nowrap: элементы остаются в одной flex-строке. Они могут сжиматься в пределах своих ограничений; само display: flex не гарантирует удобный узкий экран. Чтобы разрешить несколько строк, контейнеру задают flex-wrap: wrap.

.catalog-list {
  display: flex;
  flex-direction: row;
  flex-wrap: wrap;
  gap: 1rem;
  align-items: stretch;
}

.catalog-list > .card {
  flex: 1 1 15rem;
  min-width: 0;
  max-width: 100%;
  margin-bottom: 0;
}

Знак > выбирает непосредственных детей. Первое правило относится к контейнеру, второе — к его карточкам. Прежние фон, рамка и padding остаются в общем правиле .card. Нижний margin именно каталожных карточек обнулён: теперь промежутками управляет gap.

Часть flex: 1 1 15rem Имя Смысл
Первое 1 flex-grow Участвовать в распределении свободного места строки
Второе 1 flex-shrink Разрешить сжатие с учётом базы и ограничений
15rem flex-basis Базовый размер по главной оси до гибкого распределения

При row база относится к ширине, при column — к главному размеру по вертикали. База не является фиксированным размером или строгим минимумом. rem зависит от размера шрифта корневого html: если он равен 16px, то 15rem — 240px.

При разрешённом переносе сначала определяются элементы каждой строки с учётом их размеров и промежутков, затем место распределяется внутри каждой строки. Одиночная карточка последней строки с grow: 1 может растянуться на всю её ширину. Это ожидаемое действие выбранного правила.

min-width: 0 ослабляет автоматическое ограничение минимальной ширины flex-элемента по содержимому. Оно не переносит любую длинную строку и не уменьшает автоматически картинку. Для картинки остаются знакомые max-width: 100%; height: auto; для длинного неразрывного текста может понадобиться точное правило overflow-wrap: anywhere. Скрытие через overflow-x: hidden не делает обрезанный текст доступным.

Разобранный пример расчёта

Для учебного расчёта у трёх одинаковых карточек база 180px, flex: 1 1 180px, промежуток 20px. Внутренняя ширина контейнера — 580px. В неё уже не входят рамки и внутренние отступы родителя. У карточек действует border-box, нет внешних отступов и дополнительных ограничений размеров; содержимое не мешает сжатию.

Три карточки требуют 180 + 180 + 180 + 20 + 20 = 580px. Они помещаются в одну строку точно. Если уменьшить внутреннюю ширину контейнера до 400px, три уже не поместятся, а две потребуют 180 + 180 + 20 = 380px.

При wrap в первой строке окажутся две карточки. Оставшиеся 20px поделятся между ними поровну: внешняя ширина каждой станет 190px. Третья карточка образует отдельную строку и за счёт роста займёт все 400px. Порядок А → Б → В сохранится.

Если у тех же карточек поставить flex: 0 1 180px, они перестанут расти. Перенос сохранится, но свободное место не увеличит карточки. Это изменение первого числа, а не запрет переноса. В самостоятельной работе используйте этот способ рассуждения, подставляя её числа.

Viewport: исходные условия для мобильной страницы

Viewport — область просмотра страницы в браузере. Для этой темы важна ширина области CSS-вёрстки. CSS-пиксель не нужно приравнивать к физической точке матрицы: паспортное разрешение телефона само по себе не даёт ширину нашей раскладки.

<meta name="viewport" content="width=device-width, initial-scale=1">

Эта строка находится внутри head каждой HTML-страницы, ровно один раз.

Фрагмент Назначение
name="viewport" Настройка области просмотра для мобильного браузера
width=device-width Согласовать ширину вёрстки с шириной устройства в CSS-пикселях
initial-scale=1 Задать исходный масштаб при открытии

Без подходящей настройки мобильный браузер может использовать широкую виртуальную область вёрстки и уменьшить страницу для показа. При этом текст выглядит мелким. Метатег задаёт исходные условия, а гибкий CSS решает, как содержимому в них поместиться.

initial-scale=1 не запрещает последующее увеличение. Не добавляйте user-scalable=no или maximum-scale=1: человек должен иметь возможность увеличить страницу. Один viewport не исправляет изображение с жёсткой шириной 1000px или карточку, которой CSS запрещает сжиматься.

Ширина viewport и внутренняя ширина каталога различаются: часть места занимают поля страницы, её padding, рамки и ограничения max-width. Поэтому самостоятельная работа ниже прямо задаёт внутреннюю ширину контейнера, чтобы расчёт имел однозначный ответ.

Самостоятельная работа на бумаге

Подпишите фамилию и номер своего варианта. Обозначьте блоки 1–4. Пишите селекторы и свойства точно, рисунки сопровождайте короткими объяснениями. Переписывать весь учебный текст не нужно. После начала самостоятельной работы выполняйте её индивидуально, без подсказок и готовых ответов.

Блок 1. Выберите родителя и детей — 2 балла

Дан HTML:

<main class="page">
  <h1>Каталог</h1>
  <p>Выберите товар</p>
  <div class="catalog-list">
    <article class="card"><h2>А</h2><p>Описание А</p></article>
    <article class="card"><h2>Б</h2><p>Описание Б</p></article>
    <article class="card"><h2>В</h2><p>Описание В</p></article>
  </div>
</main>
  1. Запишите точный селектор, которому нужно назначить display: flex, чтобы он управлял тремя целыми карточками. Перечислите его непосредственных детей, которые станут flex-элементами.
  2. Объясните по дереву две ошибки: что станет flex-элементами при назначении display: flex элементу main; что станет flex-элементами при его назначении каждой .card. Почему оба выбора не решают поставленную задачу?

За пункт 1 — 1 балл при правильном родителе и полном наборе детей; за пункт 2 — 1 балл за объяснение обеих ошибок.

Блок 2. Предскажите раскладку — 4 балла

Используется правильный родитель из блока 1. У контейнера display: flex; flex-direction: row; flex-wrap: wrap; gap: 20px; justify-content: flex-start. У трёх одинаковых карточек А, Б и В: box-sizing: border-box; flex: 1 1 200px; min-width: 0; margin: 0. Дополнительных ограничений размера нет, содержимое помещается и не ограничивает расчёт. База 200px уже включает рамку и padding; повторно прибавлять их не нужно. Порядок HTML — А, Б, В.

Для каждой из трёх внутренних ширин контейнера — 640px, 440px, 300px:

  • нарисуйте строки с буквами карточек в порядке чтения;
  • подпишите итоговую ширину каждой карточки до внешних краёв рамки;
  • покажите расчёт помещения в строку и распределения остатка. Высоту карточек вычислять не нужно.

За каждую ширину — 1 балл, если верны строки, размеры и объясняющий расчёт: всего 3 балла.

Затем для контейнера 440px измените только карточки на flex: 0 1 200px. Нарисуйте новый результат, подпишите размеры и объясните, что изменилось и почему перенос остался разрешён. За полный ответ — ещё 1 балл.

Блок 3. Исправьте CSS и объясните оси — 2 балла

В каталоге из блока 1 требуется горизонтальный ряд с переносом целых карточек и промежутком 16px. Дан ошибочный код:

.card {
  display: flex;
  flex-direction: column;
  flex-wrap: wrap;
  gap: 16px;
}
  1. Перепишите правило с правильным селектором и направлением. Сохраните явное разрешение переноса и промежуток. Общие цвет, рамку и отступы карточки менять не нужно. Укажите словами, какое ошибочное назначение display следует убрать. За согласованное исправление — 1 балл.
  2. В отдельном учебном контейнере установлено flex-direction: column, есть свободное место по обеим осям, размеры детей фиксированы и не растут. Назовите главную и поперечную оси. Каким одним свойством и значением расположить группу детей в центре по вертикали? Каким другим — выровнять детей в центре по горизонтали? За обе оси и оба правильных объявления — 1 балл.

Блок 4. Исправьте viewport — 2 балла

Внутри head страницы формы находятся две строки:

<meta name="viewport" content="width=980, user-scalable=no">
<meta name="viewport" content="initial-scale=1">
  1. Замените их одной полной строкой, которая согласует ширину с устройством, задаёт исходный масштаб 1 и сохраняет возможность увеличения. Укажите место строки в HTML и перечислите, на каких из трёх страниц проекта должна быть такая настройка. За полный ответ — 1 балл.
  2. На странице с уже правильным viewport картинке задано width: 1000px, а места в карточке — 280px. Достаточно ли одного метатега? Объясните причину и запишите два объявления CSS для изображения, ограничивающие его доступной шириной и сохраняющие пропорции. За объяснение и оба объявления — 1 балл.

Самопроверка оформления листа и сдача

Убедитесь, что на листе есть имя, номер варианта, все четыре блока, три схемы для исходного flex, отдельная схема после изменения роста, исправленные CSS и HTML. У каждого расчёта подписана внутренняя ширина контейнера. Непонятный рисунок дополните словами: важен объяснимый результат, художественное качество не оценивается.

Сдайте один лист или скреплённый комплект страниц в конце работы. Запускать код или показывать собственный каталог на этой паре не требуется. Преподаватель проверяет бумажную работу вместе с уже принятым обязательным результатом пар 15–16.

Для «отлично» одновременно нужны: обязательная практика пар 15–16, 9–10 баллов за самостоятельную работу и хотя бы один балл в каждом блоке. При 0–8 баллах или нулевом блоке бумажная работа не повышает «хорошо», полученное за выполненную обязательную практику. Критерии оценок ниже «хорошо» здесь не устанавливаются.

Пара 18 продолжит практику: внесение контейнера в свой каталог, проверка единственного viewport на каждой странице, наблюдения на узкой и широкой области и доработка полного мобильного сценария. Сегодняшние бумажные расчёты — прогнозы заданной модели; они не выдаются за проверку реального проекта в браузере.
