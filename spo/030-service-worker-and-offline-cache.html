Service worker, кеширование, автономный режим и обновление приложения

Сегодня вы сделаете свой сайт доступным без интернета. Откроете проект на GitHub Pages, добавите файл sw.js и опубликуете версию 1. Затем в браузере включите режим Offline, заново откроете каталог и проверите, что поиск и форма работают.

1. Откройте свой сайт на GitHub Pages

  1. Запустите GitHub Desktop. Под Current repository выберите свой VariantNN-web. Если папки нет в списке, нажмите File → Add local repository → Choose, укажите свою существующую папку проекта и нажмите Add repository. Во вкладке History проверьте, что видите свои коммиты.
  2. В верхнем меню нажмите Repository → View on GitHub. В браузере откроется репозиторий. На вкладке Code найдите свои index.html, catalog.html и form.html.
  3. В репозитории нажмите Settings → Pages. Если размещение ещё не настроено, в разделе Build and deployment выберите Source → Deploy from a branch. В поле Branch выберите ветку, в которой лежит index.html (обычно main), рядом выберите / (root) и нажмите Save.
  4. Откройте вкладку Actions. Когда запуск pages build and deployment получит зелёную галочку, вернитесь в Settings → Pages и нажмите Visit site. Сохраните этот HTTPS-адрес: по нему вы будете проверять приложение. На открывшемся сайте перейдите с главной в каталог и форму.

Если на втором шаге сверху показана кнопка Publish repository, завершите первую отправку по статье 29, затем вернитесь сюда. Там же описано, что делать, если Pages недоступна для вашего репозитория.

Что должно получиться. В GitHub открывается история проекта, а по кнопке Visit site открывается ваше приложение с каталогом и формой.

2. Поставьте на главной отметку «Учебная версия 1»

  1. В редакторе откройте index.html в своей папке проекта. Найдите закрывающий тег первого заголовка </h1>.
  2. Вставьте эту строку сразу после </h1> и сохраните файл (Ctrl + S).
HTML
<p>Учебная версия 1</p>

Эту надпись легко найти после публикации. На следующей паре вы замените её на «Учебная версия 2» и увидите, когда браузер переключится на обновление.

3. Создайте файл sw.js и укажите, что сохранить

В редакторе создайте рядом с index.html файл sw.js и вставьте код целиком. Этот файл называется service worker. Он заранее сохраняет перечисленные страницы, стили, скрипты и картинки. Когда сети нет, браузер получает сохранённые файлы.

JavaScript
const VERSION = "v1";
const SCOPE = self.registration.scope;
const CACHE_PREFIX = `variantnn-web:${SCOPE}:`;
const CACHE_NAME = CACHE_PREFIX + VERSION;

const FILES = [
  "./",
  "./index.html",
  "./catalog.html",
  "./form.html",
  "./style.css",
  // Здесь допишите файлы своего приложения.
];

self.addEventListener("install", (event) => {
  const requests = FILES.map((path) =>
    new Request(new URL(path, SCOPE), { cache: "reload" })
  );
  event.waitUntil(
    caches.open(CACHE_NAME).then((cache) => cache.addAll(requests))
  );
});

self.addEventListener("activate", (event) => {
  event.waitUntil(
    caches.keys().then((names) => {
      const oldVersions = names.filter((name) =>
        name.startsWith(CACHE_PREFIX) && name !== CACHE_NAME
      );
      return Promise.all(oldVersions.map((name) => caches.delete(name)));
    })
  );
});

self.addEventListener("fetch", (event) => {
  const request = event.request;
  if (request.method !== "GET" || !request.url.startsWith(SCOPE)) return;

  event.respondWith(
    caches.open(CACHE_NAME).then(async (cache) => {
      const savedResponse = await cache.match(request);
      return savedResponse ?? fetch(request);
    })
  );
});
  1. В своей папке проверьте имя файла стилей. Если он называется иначе, замените "./style.css", на реальный путь.
  2. Откройте index.html, catalog.html и form.html. Найдите имена файлов в строках, которые подключают скрипты и стили. Например, если в подключении скрипта написано src="form.js", добавьте "./form.js", в список FILES перед строкой ];. Так же добавьте скрипты главной и каталога. В вашем проекте могут быть catalog.js, catalog-page.js и script.js.
  3. Добавьте изображения, которые реально показывает ваше приложение. Например, для файла images/logo.png добавьте строку "./images/logo.png",. Если каталог подставляет картинки из JavaScript, откройте каталог по адресу Pages, нажмите F12 → Network / Сеть, затем Ctrl + R. Нажмите Img, щёлкните по нужному запросу и посмотрите Headers → Request URL. Часть адреса после имени папки проекта подставьте после ./. Так же проверьте картинки, которые загружаются из CSS.
  4. Если манифест и значки уже готовы, добавьте "./manifest.webmanifest", и точные пути PNG из поля icons. Сохраните sw.js сочетанием Ctrl + S.

Сверьте имена перед отправкой

В списке каждое имя пишется в кавычках и с запятой. GitHub Pages различает Logo.png и logo.png. Если в списке есть хотя бы один отсутствующий файл, кеш этой версии не заполнится. "./", сохранит сам адрес сайта из Visit site, а "./index.html", — отдельный адрес главной страницы.

4. Добавьте подключение в три страницы

В редакторе откройте index.html, найдите внизу строку </body> и вставьте перед ней этот блок. Повторите в catalog.html и form.html. Сохраните все три файла.

HTML
<script>
  if ("serviceWorker" in navigator) {
    navigator.serviceWorker.register("./sw.js").catch((error) => {
      console.error("Не удалось зарегистрировать service worker:", error);
    });
  }
</script>

Когда вы откроете любую из этих страниц по адресу GitHub Pages, браузер получит команду запустить sw.js из папки вашего проекта.

5. Отправьте версию 1 и проверьте размещение

  1. В GitHub Desktop откройте Changes. Убедитесь, что галочки стоят у index.html, catalog.html, form.html, нового sw.js и новых ресурсов, если вы их добавляли.
  2. Слева внизу в поле Summary напишите Добавлена автономная версия 1. Нажмите синюю кнопку Commit to main. Если у вас другое имя рабочей ветки, оно будет в тексте кнопки. Сверху нажмите Push origin.
  3. Нажмите Repository → View on GitHub. На вкладке Code проверьте, что в ветке размещения видны надпись коммита Добавлена автономная версия 1 и файл sw.js.
  4. Откройте Actions и найдите запуск для этого коммита. Дождитесь зелёной галочки. Вернитесь в Settings → Pages → Visit site. Если на главной видна надпись Учебная версия 1, вы открыли опубликованный результат. Добавьте к адресу сайта sw.js и проверьте, что открывается код со строкой const VERSION = "v1";.

Как понять, где вы остановились

Commit сохраняет изменения в истории на компьютере. Push origin отправляет их на GitHub. Зелёная галочка в Actions означает, что GitHub Pages закончил размещение. Если зелёной галочки ещё нет, сначала проверьте статус запуска.

6. Выключите сеть в браузере и проверьте сайт

  1. На своём сайте откройте F12 → Application / Приложение. Если вкладка скрыта, нажмите » справа в верхней строке инструментов. Слева выберите Service Workers, найдите sw.js и дождитесь состояния activated. Нажмите Ctrl + R.
  2. В разделе Service Workers оставьте Update on reload и Bypass for network выключенными. Слева раскройте Cache Storage и выберите кеш с окончанием :v1. В списке должны быть catalog.html, form.html и ваши файлы стилей и скриптов.
  3. Вернитесь в Service Workers и поставьте галочку Offline. Оставьте инструменты открытыми. Нажмите Ctrl + R и проверьте, что главная страница снова открылась с надписью Учебная версия 1.
  4. Перейдите в каталог по ссылке на сайте. Введите запрос, по которому вы знаете, что должно остаться в выдаче. Проверьте карточки, картинки и счётчик. Затем откройте форму, введите свои учебные значения, нажмите кнопку расчёта и проверьте сообщение.
  5. Позовите преподавателя к своему компьютеру и выполните показ по инструкции ниже.

Если sw.js виден, но кеш пуст, откройте вкладку Console / Консоль и покажите преподавателю сообщение ошибки. Если каталог без сети открывается без оформления или без картинок, в Network / Сеть найдите имя не загрузившегося файла и сверьте его со списком FILES. Для исправления уже опубликованной рабочей версии измените и список, и номер в строке const VERSION, затем повторите отправку. На второй паре будете увеличивать последний рабочий номер.

Что показать преподавателю

Показывайте результат прямо на своём компьютере, во вкладке браузера с вашим приложением на GitHub Pages. Это HTTPS-адрес, который открылся по кнопке Visit site на шаге 5. Оставьте рядом открытыми инструменты разработчика (F12).

  1. На главной странице покажите надпись Учебная версия 1. В Application → Cache Storage откройте кеш :v1 и покажите, что в нём есть catalog.html и form.html.
  2. Перейдите в Application → Service Workers. Убедитесь, что стоит галочка Offline, и нажмите Ctrl + R при преподавателе.
  3. В той же вкладке перейдите в каталог и выполните поиск или откройте форму и покажите расчёт. Затем снимите галочку Offline.

Если сайт пока не открылся, покажите последний успешный шаг в GitHub Desktop или на GitHub и сообщение, на котором остановились.

Без сети работают действия, которые скрипты выполняют на устройстве, например фильтр по готовому списку и расчёт формы. На следующей паре вы проверите запуск с телефона и повторите публикацию, чтобы увидеть, как первая версия сменяется второй.
