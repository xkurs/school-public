Service worker, кеширование, автономный режим и обновление приложения

На предыдущей паре мы начали отправлять VariantNN-web на GitHub, размещать сайт через GitHub Pages и добавлять манифест. Если вы остановились на одном из этих этапов, сегодня продолжите с него. Представьте, что телефон потерял сеть уже после первого открытия приложения. Сможет ли он заново открыть каталог, применить фильтр и показать результат расчёта в форме? Для этого браузеру нужны локальные копии страниц и всех файлов, от которых они зависят.

Что именно браузер сохраняет

Механизм Что он даёт нашему проекту
manifest.webmanifest Название, значки и начальную страницу для установленного приложения
localStorage Значение, которое записал код страницы, например последний запрос поиска
Cache Storage Именованные наборы ответов на запросы, например копии catalog.html, style.css и catalog-page.js
Service worker Скрипт, который может выбрать для запроса управляемой страницы сохранённый ответ или обратиться к сети

При открытии catalog.html браузер получает HTML, затем по указанным в нём адресам запрашивает CSS, JavaScript и изображения. Если сохранить только HTML, без сети может появиться текст каталога, но потеряться оформление или поиск. Если сохранить все ресурсы каталога, поиск по локальному массиву выполняется без сети, а прежний запрос можно восстановить из localStorage. Это две отдельные проверки.

Что происходит с формой

Если form.js рассчитывает результат из введённых значений на самом устройстве, этот расчёт может работать в автономном режиме. Для отправки данных на сервер потребуется сеть. Обновление кеша также не добавляет сохранение полей формы: их восстановление зависит от кода самой формы.

Как service worker получает управление

Service worker работает в отдельном контексте браузера. Он получает события загрузки и обновления, но у него нет доступа к document страницы и её localStorage. Страница регистрирует скрипт по HTTPS или на http://localhost на том же компьютере. Открытие HTML двойным щелчком по file:// для этой работы не подходит.

Файл sw.js положим рядом с index.html, catalog.html и form.html. Тогда область управления по умолчанию — папка проекта и её вложенные папки. Если Pages разместил проект по адресу https://ваш-логин.github.io/VariantNN-web/, эта область начинается с /VariantNN-web/. Относительный адрес ./sw.js сохраняет этот путь. Область из манифеста относится к запуску и навигации установленного приложения, область регистрации service worker определяет, какие страницы он может контролировать.

Событие Что делает учебный скрипт Что наблюдаем
install Загружает заранее перечисленные ресурсы в кеш версии Пропущенный файл или ответ 404 срывает установку этой версии
activate После перехода на новую версию удаляет прежние кеши этого проекта Остаётся кеш текущей версии, кеши соседних проектов сохраняются
fetch Для GET-запроса ищет точный адрес в кеше текущей версии и при промахе обращается к сети При отключённой сети работает то, для чего есть сохранённый ответ

event.waitUntil(...) сообщает браузеру, что событие установки или активации ещё обрабатывается. event.respondWith(...) передаёт браузеру обещание получить ответ на запрос. Сама регистрация подтверждает, что браузер принял регистрацию скрипта. Завершение установки и появление управления проверяем отдельно.

Разбор запроса без сети

Вкладка каталога находится под управлением service worker. Студент открывает форму по адресу form.html.

  1. Для form.html есть сохранённый ответ. Браузер получает его из кеша.
  2. HTML подключает form.js. Если этот адрес тоже в кеше, форма рассчитывает результат локально.
  3. HTML ссылается на images/banner.png, которого в списке кеша нет. Скрипт обращается к сети, и изображение при отключённой сети не загрузится.

В нашей стратегии для перечисленных файлов сначала проверяем кеш. Остальные запросы идут по сети, а их ответы автоматически в кеш не добавляются. Адреса ./, ./index.html и ./index.html?demo=1 различаются. В работе сохраним первые два адреса отдельно, чтобы открывались и ссылка на папку, и стартовая страница из манифеста.

Что проверить на экране

После обычной перезагрузки откройте Application → Service Workers и Cache Storage. Найдите sw.js, проверьте управление текущей страницей и конкретные адреса в кеше. Затем включите Offline и снова загрузите страницу. Уже видимый экран может оставаться на месте без сети даже при неработающем кеше.

Как приложение переходит на новую версию

Если поменять одну подпись в index.html, текущий service worker по-прежнему может отдавать старую копию из кеша. Поэтому вместе с изменением сохраняемых файлов меняем версию в sw.js с v1 на v2. Браузер при проверке обновления получает изменённый скрипт. Новый worker скачивает комплект v2, а уже открытые страницы продолжают работать с v1.

  1. Загрузка комплекта. Пока в браузере есть сеть, новый worker заполняет свой кеш. Ошибка получения обязательного файла прерывает установку, прежняя версия остаётся доступной.
  2. Ожидание. Успешно установленный worker ждёт, пока завершится работа страниц, которые контролирует старая версия. Сюда входят вкладки проекта и отдельное окно установленного приложения в том же браузере и профиле.
  3. Активация. Когда старые страницы закрыты, новая версия активируется и очищает старые кеши этого проекта. При следующем открытии видна новая подпись. В браузере того же профиля и по тому же адресу ранее сохранённый поисковый запрос остаётся в localStorage.

Что считать доказательством обновления

Покажите новую подпись и присутствие кеша v2, затем заново загрузите обновлённую страницу без сети. Во время проверки оставьте выключенными Update on reload и Bypass for network, чтобы инструменты разработчика сохраняли обычное поведение браузера.

Вопросы перед практикой

  1. Какие ответы нужны кроме catalog.html, чтобы каталог без сети выглядел и работал как прежде?
  2. Студент видит значок приложения и открывает его при работающей сети. Как отдельно проверить автономный запуск?
  3. В списке ресурсов images/logo.png, а на сайте есть только images/Logo.png. В какой момент обнаружится расхождение?
  4. После отправки новой версии браузер показывает waiting. Что произойдёт, если оставить одну вкладку проекта открытой?

1. Откройте свой проект через браузер

Сначала убедитесь, что главная, каталог и форма работают онлайн. Для проверки своих ещё не отправленных изменений откройте папку VariantNN-web через доступный в аудитории локальный сервер и используйте напечатанный им адрес http://localhost:…. Если на компьютере есть Python, можно запустить обычную раздачу файлов из корня проекта в терминале PowerShell:

PowerShell
python -m http.server 8000 --bind 127.0.0.1

Оставьте терминал открытым и перейдите на http://localhost:8000/ на том же компьютере. Если команда не найдена, используйте локальный сервер, уже доступный в редакторе, или проверяйте изменения на своём опубликованном после отправки файлов HTTPS-сайте. На протяжении проверки одной версии используйте один и тот же адрес, включая порт.

2. Составьте список адресов

Откройте F12 → Network / Сеть и по очереди загрузите три страницы, пока сеть доступна. Посмотрите, какие CSS и JS подключаются, какие изображения нужны каталогу и откуда они загружаются. Допишите к шаблону ниже все реальные локальные зависимости. Проверьте написание имён и регистр букв: на Pages Logo.png и logo.png — разные имена.

Если проект ещё без манифеста и значков, сначала проверьте кеш основных страниц, а эти файлы добавьте при их готовности. Каждый элемент списка должен открываться с успешным ответом. Для этой работы автономный набор состоит из локальных файлов проекта. Сетевой ресурс, которого нет в этом наборе, может пропасть без сети.

3. Создайте sw.js рядом с index.html

JavaScript
const VERSION = "v1";
const SCOPE = self.registration.scope;
const CACHE_PREFIX = `variantnn-web:${SCOPE}:`;
const CACHE_NAME = CACHE_PREFIX + VERSION;

const FILES = [
  "./",
  "./index.html",
  "./catalog.html",
  "./form.html",
  "./style.css",
  // Добавьте реальные JS, CSS, картинки, манифест и значки своего проекта.
];

self.addEventListener("install", (event) => {
  const requests = FILES.map((path) =>
    new Request(new URL(path, SCOPE), { cache: "reload" })
  );
  event.waitUntil(
    caches.open(CACHE_NAME).then((cache) => cache.addAll(requests))
  );
});

self.addEventListener("activate", (event) => {
  event.waitUntil(
    caches.keys().then((names) => {
      const oldVersions = names.filter((name) =>
        name.startsWith(CACHE_PREFIX) && name !== CACHE_NAME
      );
      return Promise.all(oldVersions.map((name) => caches.delete(name)));
    })
  );
});

self.addEventListener("fetch", (event) => {
  const request = event.request;
  if (request.method !== "GET" || !request.url.startsWith(SCOPE)) return;

  event.respondWith(
    caches.open(CACHE_NAME).then(async (cache) => {
      const savedResponse = await cache.match(request);
      return savedResponse ?? fetch(request);
    })
  );
});

Для учебного VariantNN-web проверьте, нужны ли ./catalog.js, ./catalog-page.js, ./form.js и ./script.js. Такой элемент, как "./images/icon-192.png",, добавляйте внутрь массива при наличии файла по этому адресу. Если подключено несколько листов стилей, учитывайте также локальные url(...) в CSS. cache: "reload" просит браузер получить свежие копии при заполнении новой версии, минуя его обычный HTTP-кеш. Строка CACHE_PREFIX включает адрес папки, чтобы у двух проектов на одном домене были разные кеши.

4. Зарегистрируйте скрипт на трёх страницах

Перед </body> в index.html, catalog.html и form.html добавьте один и тот же блок. Код самой страницы, например подключение form.js, сохраняется.

HTML
<script>
  if ("serviceWorker" in navigator) {
    navigator.serviceWorker.register("./sw.js").catch((error) => {
      console.error("Не удалось зарегистрировать service worker:", error);
    });
  }
</script>

Сохраните файлы. Для проверки по HTTPS выполните шаг 5. Если пока работаете на localhost, переходите к шагу 6.

5. Опубликуйте первую версию через GitHub Pages

  1. В GitHub Desktop откройте Changes. Проверьте три изменённых HTML, новый sw.js и файлы манифеста, значков или других ресурсов, если их добавили сейчас. Убедитесь, что каждый путь из FILES есть в отправляемой версии проекта.
  2. В Summary напишите Подключён service worker v1, нажмите Commit to …, затем Push origin. Откройте репозиторий в браузере и найдите этот коммит в ветке размещения. Проверьте, что в ней рядом с index.html появился sw.js.
  3. В Actions дождитесь успешного размещения этого коммита. Откройте сайт по HTTPS и добавьте к адресу папки sw.js. Например, https://логин.github.io/репозиторий/sw.js должен отдавать текст JavaScript с вашей версией. Затем откройте главную, каталог и форму по HTTPS.

Где остановилась отправка

Commit сохраняет работу на компьютере. Push origin передаёт коммит в репозиторий на GitHub. Pages после успешного размещения отдаёт файлы по адресу приложения. Подтвердите свой этап в History, на GitHub или на рабочей странице по HTTPS.

6. Покажите результат первой версии

Откройте приложение онлайн. В Application → Service Workers найдите активный sw.js, затем выполните обычную перезагрузку (Ctrl + R). В консоли navigator.serviceWorker.controller?.scriptURL должен вывести адрес sw.js. Если результат undefined, проверьте регистрацию, область управления и ошибки установки.

  1. В Application → Cache Storage раскройте кеш …:v1 и найдите catalog.html, подключённый скрипт каталога и его картинки. При необходимости обновите список кешей кнопкой панели.
  2. В Application → Service Workers включите Offline. Перезагрузите каталог обычным способом и введите запрос с известным результатом. Проверьте карточки и счётчик.
  3. Перейдите в форму по ссылке приложения. Введите данные для одного известного расчёта и проверьте сообщение под кнопкой. Проверьте переход на главную.
  4. Верните режим Online. Если сломалось оформление или действие, найдите отсутствующий адрес в Network. При изменении списка уже активной версии увеличьте VERSION; для следующей пары используйте два соседних номера, начиная с последнего рабочего.

Что показать в конце первой пары

Покажите адрес под управлением sw.js, содержимое кеша и каталог или форму после повторной загрузки без сети. Для подготовки к проверке на телефоне покажите также HTTPS-адрес с опубликованным sw.js. Если проверили только localhost, укажите, на каком этапе остановилось размещение.
