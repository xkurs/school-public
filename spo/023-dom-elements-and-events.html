DOM и события: поиск элементов, изменение страницы и обработчики

Сегодня лекция с демонстрацией: программа впервые меняет саму страницу, а не только консоль. Разберём, как найти элемент, заменить его текст, создать новый блок и отреагировать на действие пользователя.

Что должно получиться: на своей главной странице вы выводите число записей каталога, показываете список названий по нажатию кнопки и понимаете, как перехватывается отправка формы. Следующие две пары — практика на форме и каталоге.

Рабочий ритм: изменить → сохранить → обновить страницу → проверить.

1. Проверьте исходное состояние

Откройте свою папку VariantNN-web. В index.html подключён catalog.js; в консоли видны три блока карточек и расчёт выбранной записи; в catalog.html лежат три готовые карточки.

Сделайте: обновите главную страницу и убедитесь, что каталог и расчёт работают. Если что-то пропало, восстановите по паре 21: сегодняшняя работа опирается на массив catalog.

Проверьте: в index.html есть заголовок первого уровня и текст о приложении, которые вы будете дополнять, а не заменять.

2. Страница — это дерево элементов

Браузер читает HTML и строит из него DOM — объектную модель документа. Каждый тег становится элементом: у страницы есть корень document, внутри — html, head, body, а в body — ваши заголовки, абзацы, списки и карточки.

JavaScript видит эту структуру и может её менять. Важно: изменения в DOM видны сразу на экране, но исходный файл HTML не меняется. После обновления страницы браузер снова строит DOM из файла, поэтому все изменения пропадают. Это нормально: программа создаёт их заново при каждом запуске.

Проверьте: откройте index.html, нажмите F12, выберите вкладку Elements / Элементы. Наведите курсор на строку с заголовком — браузер подсветит его на странице.

3. Найдите элемент: querySelector

Чтобы изменить элемент, его нужно сначала найти. Самый простой способ — document.querySelector с CSS-селектором в кавычках; тот же синтаксис вы уже использовали в стилях: #status — элемент с id="status", .card — элемент с классом card.

Добавьте в index.html после заголовка пустой абзац:

HTML
<p id="status" role="status"></p>

id должен быть уникальным на странице. role="status" подсказывает вспомогательным технологиям, что текст обновляется программно.

Теперь в конце catalog.js:

JavaScript
const status = document.querySelector("#status");
status.textContent = "Записей в каталоге: " + catalog.length;

Что произошло: querySelector вернул элемент, textContent заменил его текст. Строка собирается из подписи и числа — так же, как в консольных опытах прошлой пары.

Проверьте: обновите страницу — под заголовком появилось «Записей в каталоге: 3» (или ваше число). В консоли ошибки нет.

Если браузер пишет Cannot set properties of null, элемент не найден: проверьте id в HTML и в селекторе, регистр букв и то, что скрипт подключён с defer и выполняется после построения страницы.

4. Меняйте текст, а не разметку

textContent записывает текст: любые угловые скобки в нём останутся видимыми символами, а не превратятся в теги. Это безопасно, когда текст приходит из данных.

JavaScript
const first = catalog[0].name;
status.textContent = first + " — " + catalog.length + " записей";

Свойство innerHTML вставляет разметку и выполняет её как HTML. Для названий карточек, введённых пользователем строк и любых данных используйте textContent: тогда случайные символы не сломают страницу. innerHTML допустим только для разметки, которую написали вы сами.

Сделайте: выведите в #status название первой карточки и число записей, соединив части строки.

Проверьте: название отображается точно так же, как в catalog.html, без лишних кавычек.

5. Создайте элементы: createElement и append

Текст в готовый абзац — просто. Но список названий заранее в HTML не написан: его составляет программа. Элемент создают отдельно, заполняют и вставляют в нужное место.

Добавьте в index.html кнопку и пустой список:

HTML
<button id="show-names" type="button">Показать названия</button>
<ul id="names"></ul>

type="button" обязателен: без него кнопка внутри формы вела бы себя как кнопка отправки. Здесь формы нет, но привычку сохраняйте.

Теперь в catalog.js:

JavaScript
const namesList = document.querySelector("#names");

function renderNames() {
  namesList.replaceChildren();
  for (const item of catalog) {
    const line = document.createElement("li");
    line.textContent = item.name;
    namesList.append(line);
  }
}

Порядок действий:

Действие Запись
Создать элемент списка document.createElement("li")
Заполнить текстом line.textContent = item.name
Вставить в конец списка namesList.append(line)
Очистить список перед новым выводом namesList.replaceChildren()

replaceChildren() без аргументов удаляет всё содержимое. Без очистки каждый вызов добавлял бы новые пункты к прежним.

Проверьте: вызовите renderNames() в консоли — в списке три пункта с вашими названиями. Вызовите ещё раз: пунктов по-прежнему три, а не шесть.

6. Реагируйте на действие: addEventListener

Пока функция вызывается вручную из консоли. Пользователь так работать не будет: ему нужна кнопка. Событие — действие в браузере: клик, ввод, отправка формы, нажатие клавиши.

JavaScript
const showButton = document.querySelector("#show-names");
showButton.addEventListener("click", renderNames);

addEventListener принимает имя события строкой и функцию, которая выполнится при событии. Обратите внимание: renderNames передаётся без скобок. renderNames() вызвал бы функцию сразу, а нам нужна ссылка на неё.

Сделайте: нажмите кнопку. Список заполнится. Нажмите ещё раз — список обновится, дублей не будет.

Проверьте: до нажатия список пуст; после первого нажатия в нём три пункта; после второго — снова три.

Функция-обработчик может быть и безымянной. Замените прежнюю строку addEventListener этой записью, иначе на клик будут реагировать два обработчика:

JavaScript
showButton.addEventListener("click", function () {
  status.textContent = "Список показан";
});

Такой обработчик удобен для одного-двух действий. Если логика больше, выносите её в отдельную функцию с именем.

7. Отправка формы: submit и preventDefault

Форма ведёт себя особо: по нажатию кнопки браузер собирает значения полей и переходит на адрес из action или перезагружает страницу с параметрами в адресной строке (у вашей формы method="get"). Программе это мешает: страница обновится, и сообщение исчезнет.

Событие отправки перехватывают так. На странице с формой (form.html) создайте временный абзац <p id="status" role="status"></p> перед кнопкой отправки, подключите скрипт и добавьте обработчик:

JavaScript
const status = document.querySelector("#status");
const form = document.querySelector("form");
form.addEventListener("submit", function (event) {
  event.preventDefault();
  status.textContent = "Форма отправлена";
});

event.preventDefault() отменяет стандартное поведение браузера: перехода и перезагрузки не будет. Дальше в обработчике можно прочитать поля и показать результат на странице — этим займёмся на практике; там временный абзац заменяется отдельным местом для сообщения.

Проверьте: добавьте обработчик на страницу с формой, заполните поля и нажмите кнопку. Адресная строка не меняется, страница не перезагружается, появляется сообщение.

Осторожно: браузер сначала выполняет встроенную проверку (required, type="number"). Если поле пустое или заполнено неверно, событие submit не наступит и обработчик не выполнится.

  1. Добавьте кнопку «Скрыть названия», которая очищает список через replaceChildren().
