Обработка формы и вывод результата с сообщениями об ошибках

Сегодня форма начнёт отвечать на нажатие кнопки. Продолжайте свою папку проекта и свой form.html после пары 14. Функция getResult и две числовые величины уже написаны на паре 20; перенесём их в новый файл без изменений.

Результат: при отправке формы страница не перезагружается, а под кнопкой появляется сообщение с названием выбранной позиции и итогом или причиной отказа. Рабочий ритм: изменить → сохранить → обновить страницу → проверить. Новый файл один — form.js рядом с form.html. Прежние conditions.js, catalog.js и script.js сохраните.

1. Место для сообщения

Если на паре 23 вы добавляли на страницу формы временный абзац #status и относящийся к нему код, удалите их: сегодня сообщение выводится в #result, а обработчик будет в form.js.

В form.html найдите кнопку отправки. Сразу после неё, внутри формы, добавьте пустой абзац:

HTML
<p id="result" role="status" aria-live="polite"></p>

id="result" — имя для поиска из JavaScript. role="status" и aria-live="polite" сообщают вспомогательным технологиям, что текст в этом абзаце обновляется и его нужно прочитать, не прерывая пользователя. Пока абзац пуст, на странице ничего не видно.

Проверьте: сохраните form.html и обновите форму. Внешний вид не изменился; в инструментах разработчика (F12 → Elements / Элементы) абзац находится после кнопки и внутри form.

2. Подключите новый файл

Создайте рядом с form.html файл form.js. В form.html перед закрывающим </body> добавьте:

HTML
<script src="form.js" defer></script>

src указывает путь к файлу, defer откладывает выполнение до окончания разбора HTML. К этому моменту абзац и поля уже существуют. Подключение нужно на странице формы, а не на главной. Постоянные файлы проекта и их подключения не удаляйте.

В form.js временно напишите:

JavaScript
console.log("Форма запущена");

Сохраните оба файла, откройте form.html, нажмите F12 и выберите Console / Консоль. Обновите страницу: строка появилась — файл подключён. Уберите временный вывод.

3. Перехватите отправку

В form.js добавьте:

JavaScript
const form = document.querySelector("form");

document.querySelector("form") находит первый элемент form на странице. Подпишитесь на событие отправки:

JavaScript
form.addEventListener("submit", function (event) {
  event.preventDefault();
});

addEventListener связывает событие с функцией-обработчиком: она выполнится при отправке. event.preventDefault() отменяет действие браузера по умолчанию.

Что будет без этой строки. У формы method="get". Браузер соберёт значения полей, добавит их в адрес после ? и перезагрузит страницу. Абзац результата снова станет пустым, а введённые значения вернутся к начальным. preventDefault() оставляет нас на странице: дальше сообщение показываем сами.

Проверьте: заполните обязательные поля корректно. Внутри обработчика временно добавьте console.log("Отправка перехвачена");, сохраните и нажмите кнопку. В консоли появилась строка, адресная строка не изменилась, страница не перезагрузилась. Уберите временный вывод.

4. Прочитайте количество

Внутри обработчика, после event.preventDefault();, добавьте:

JavaScript
const quantityText = document.querySelector("#quantity").value;

#quantity — селектор по id. Свойство .value возвращает строку — то, что сейчас введено в поле. Даже у type="number" это строка; преобразование в число делает getResult. Если поле пустое, .value даёт пустую строку "".

Проверьте: временно выведите console.log(quantityText); и console.log(typeof quantityText);. Введите 3 — увидите 3 и string. Уберите временные выводы.

5. Получите название выбранной позиции

Там же добавьте:

JavaScript
const select = document.querySelector("#item");
const itemName = select.options[select.selectedIndex].text;

select.options — все пункты option по порядку, индексы начинаются с 0. select.selectedIndex — номер выбранного пункта, а select.options[select.selectedIndex] — сам пункт. У пункта .text — видимая подпись, а .value — служебное значение из атрибута value. Для сообщения нужно название, поэтому берём .text; select.value даст служебное item2, а не название позиции.

Проверьте: временно выведите itemName и выберите вторую и третью позиции по очереди. В консоли меняется название. При пустом выборе браузер не отправит форму, пока позиция не выбрана.

6. Вызовите готовую функцию

Перенесите в начало form.js своё объявление getResult из рабочего файла (conditions.js или catalog.js) и две числовые константы unitValue и extraValue. Функцию не переписывайте: она уже возвращает итог или сообщение об ошибке. Массив каталога, цикл и старые проверочные вызовы сюда не переносите. Константы сохраните с теми же значениями и смыслом, что на паре 20.

Внутри обработчика после чтения полей добавьте:

JavaScript
const message = getResult(quantityText, unitValue, extraValue);

Аргументы идут по порядку параметров: текст количества, величина на единицу, общая добавка. Первый аргумент теперь приходит из поля, а не задан в файле.

Проверьте: временно выведите console.log(message); и отправьте форму с корректным количеством. В консоли появился итог, совпадающий с расчётом пары 20. Случаи с ошибками проверим в разделе 10, когда временно отключим встроенную проверку.

7. Покажите сообщение на странице

Рядом с const form, до обработчика, объявите ссылку на абзац:

JavaScript
const result = document.querySelector("#result");

В конце обработчика добавьте:

JavaScript
result.textContent = message;

textContent заменяет текст внутри абзаца. Это именно текст, а не разметка: угловые скобки и теги в сообщении останутся видимыми символами. innerHTML здесь не нужен — он разбирал бы строку как HTML. alert блокирует страницу, а console.log виден только разработчику: пользователь сообщения не увидит.

Проверьте: введите корректное количество и нажмите кнопку. Под кнопкой появился итог. Нажмите ещё раз — абзац заменился, второй копии нет. Измените количество — сообщение обновилось.

8. Добавьте название позиции

Сейчас сообщение не говорит, для какой позиции сделан расчёт. Замените строку вывода:

JavaScript
result.textContent = itemName + ". " + message;

Знак + соединяет строки, а точка с пробелом разделяют название и сообщение. Теперь у каждой позиции свой итог, и сообщение об ошибке тоже остаётся привязанным к выбранному названию.

Проверьте: выберите другую позицию, не меняя количества. Название в сообщении изменилось. Верните прежнюю позицию.

9. Встроенная проверка и собственная

Браузер уже проверяет форму по атрибутам: required у списка и количества, type="number", min="1", step="1". Пустую форму он не отправит, а при нуле или дроби покажет своё сообщение. Поэтому обработчик submit может вообще не выполниться.

Собственная проверка в getResult всё равно нужна: атрибуты можно обойти или отключить, функцию можно вызвать не только из формы, а встроенная проверка не знает правил вашего расчёта. Сообщение должно быть понятным и одинаковым для всех случаев, а проверку нужно уметь объяснить и перенести в другую программу.

Чтобы увидеть свои сообщения, временно добавьте в существующий тег form атрибут novalidate:

HTML
<form method="get" novalidate>

Теперь браузер не блокирует отправку, и обработчик получает даже пустое поле. После испытаний обязательно верните form без novalidate: встроенная проверка должна снова работать вместе с собственной. Числовое поле не даёт набрать слово или одни пробелы: браузер оставляет его пустым. Чтобы проверить сообщения «введите число» и «укажите количество», на два опыта временно замените type="number" на type="text", а затем верните type="number", min и step.

10. Испытайте форму

Выполняйте проверки по одной и возвращайте исходные атрибуты после временных изменений. Перед опытами выберите настоящую позицию: приглашение «Выберите из списка» не является названием. Вид и текст сообщений браузера могут отличаться; проверяется поведение, а не совпадение фразы с образцом.

Проверка Что временно изменить Ожидаемый результат
Корректное количество Ничего Под кнопкой: название позиции, подпись итога и число
Количество на 1 больше Ничего Итог вырос ровно на unitValue; добавка осталась одной
Пустое количество novalidate у формы «Укажите количество»; суммы в сообщении нет
Только пробелы novalidate, type="text" «Укажите количество»; суммы нет
Слово вместо числа novalidate, type="text" «Введите число»; суммы нет
Ноль novalidate «Нужно положительное целое количество»
Дробное 1.5 novalidate «Нужно положительное целое количество»
Адресная строка Любая отправка Адрес не меняется, страница не перезагружается
Ошибка без расчёта novalidate, любой неверный ввод В сообщении нет подписи итога и рассчитанного числа

Проверьте отдельно: после нажатия кнопки в адресе нет ?item=…&quantity=…, а введённые значения и сообщение остаются на месте. Если страница мигнула и значения сбросились, preventDefault() не выполняется. После опытов уберите novalidate и верните type="number", min и step. Финальная проверка — с работающей встроенной проверкой: пустое поле и ноль браузер не пропускает, а корректное количество показывает ваше сообщение.

Покажите результат

Покажите form.html и form.js:

  • абзац #result после кнопки, подключение form.js и обработчик с event.preventDefault();
  • чтение #quantity и #item, вызов getResult и вывод через textContent, один корректный расчёт и один отказ по выбору преподавателя.

Объясните, что произошло бы без preventDefault, чем .value отличается от .text и почему сообщение выводится в абзац, а не в alert. Для показа собственного отказа временно включите novalidate, после показа верните атрибут.

Если закончили раньше

Добавьте счётчик отправок. Перед обработчиком объявите let submitCount = 0;, а внутри обработчика увеличьте его: submitCount = submitCount + 1;. Затем добавьте номер проверки в начало сообщения:

JavaScript
result.textContent = "Проверка " + submitCount + ". " + itemName + ". " + message;

Проверьте: первое нажатие даёт «Проверка 1», второе — «Проверка 2» без перезагрузки страницы. После обновления страницы счёт снова начинается с единицы. При испытаниях с novalidate решите, считать ли ошибочные отправки, и объясните выбор.
