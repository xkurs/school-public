Доработка PWA: проверка ввода, сохранения данных и поведения без сети

На экзамене через три недели вам предстоит скачать собственное веб-приложение с GitHub и переделать его под конкретное условие. Например, из вашего каталога может получиться магазин настольных игр с поиском и расчётом стоимости заказа. Сегодня на первой паре вы готовите рабочую основу, на второй — репетируете изменение данных и сдачу результата.

Содержание

  • Что проверит преподаватель в конце второй пары

Что проверит преподаватель в конце второй пары

  1. На локальном сервере вы показываете изменённый товар в каталоге и форме, правильную стоимость двух единиц и отказ при ошибочном количестве без старого итога на экране.
  2. На GitHub вы показываете свой репозиторий с последним коммитом и проверяете, что по адресу GitHub Pages открылась именно эта версия: с новой карточкой, изображением и рабочими переходами.
  3. На телефоне вы открываете приложение с выключенной связью, переходите в каталог и показываете, что поиск работает, а запрос и результат сохраняются при обновлении страницы.
  4. В редакторе вы показываете, где изменили данные, и объясняете, откуда форма берёт цену.

Последовательность действий для итогового показа есть в статье второй пары.

Получите свой проект с GitHub

  1. Откройте на GitHub репозиторий своего VariantNN-web. Сверьте владельца, название, ветку и последний коммит. В списке файлов найдите главную страницу, каталог, форму, стили и скрипты.
  2. В GitHub Desktop откройте File → Clone repository, выберите свой репозиторий или вставьте его URL. Укажите новую папку для копии, чтобы сохранить прежнюю рабочую папку. Откройте скачанную папку в редакторе и сверьте последний коммит в History с GitHub. Так вы проверите, что сможете получить исходники на другом компьютере.
  3. Если в старой папке работа новее, откройте её в Desktop, посмотрите Changes и History. Сохраните нужные правки коммитом и отправьте их на GitHub. Получите этот коммит в скачанной копии и дальше работайте в ней. Если репозитория пока нет, начните с первой отправки на GitHub. При проблеме со входом или сетью продолжайте с доступной локальной копией и отметьте, что скачивание ещё нужно проверить.

Запустите проект на локальном сервере

Откройте скачанную папку VariantNN-web, где лежит index.html. Если в редакторе уже есть локальный сервер, запустите через него эту папку и откройте адрес, который он покажет.

Иначе откройте терминал в папке проекта. В Windows можно ввести cmd в адресной строке Проводника и нажать Enter. Если на компьютере есть Python, скопируйте в терминал только эту строку, начиная с python:

Код
python -B -m http.server 8000 --bind 127.0.0.1

Если в Windows команда python не найдена, попробуйте заменить первое слово на py. Если Python отсутствует, установите Python 3 с официального сайта, заново откройте терминал в папке проекта и повторите команду.

После успешного запуска Python покажет строку Serving HTTP on .... Оставьте терминал открытым и перейдите в браузере на http://localhost:8000/. Если порт занят или на нём открывали чужой проект с service worker, выберите другой свободный порт и укажите его и в команде, и в адресе.

Перейдите с главной в каталог и форму. Сверьте название своего проекта и проверьте, что загрузились стили, изображения и скрипты. Если видите старую версию, проверьте папку сервера, затем состояние service worker по инструкции по обновлению. Для проверки свежих правок с работающей сетью можно временно включить Bypass for network в F12 → Application → Service Workers на локальном адресе.

Пройдите по строкам сверху вниз. Если результат уже есть, переходите к следующей строке. Если части не хватает, откройте указанный раздел, повторите шаги со своими данными и снова проверьте результат.

Проверьте форму перед второй парой

  1. Выберите позицию и заранее вычислите ожидаемый итог для количества 2 по своему варианту. Если в расчёте есть общая добавка extraValue, учтите её один раз. Введите 2 и сравните результат формы с прогнозом.
  2. Очистите количество и попробуйте отправить форму. Затем по очереди попробуйте 0 и 1.5. Ожидаются сообщение браузера или приложения и отсутствие прежнего итога. Снова введите 2 и проверьте, что расчёт восстановился.
  3. Если прежний итог остаётся, проверьте, что при изменении полей обработчик input очищает элемент с результатом. Например, если ссылки на форму и результат называются form и result, добавьте после их объявления:

javascript form.addEventListener("input", function () { result.textContent = ""; });

Встроенная проверка может остановить отправку до запуска обработчика submit. Повторите весь опыт после правки. 4. Если что-то пришлось восстановить, проверьте изменения и запишите их отдельным коммитом. Оставьте себе название проверенного товара, цену, ожидаемый итог и список шагов, которые ещё требуют проверки. Переходите к репетиции задания.
