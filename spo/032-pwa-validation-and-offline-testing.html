Доработка PWA: проверка ввода, сохранения данных и поведения без сети

Продолжайте свой VariantNN-web с последней работающей версии. На предыдущей практике вы проверяли, открывается ли приложение после отключения сети и смены версии. Теперь проверьте, можно ли в открывшемся приложении выполнить полезное действие: получить верный итог в форме, найти карточку и вернуться к тому же результату поиска после перезагрузки.

Содержание

  • Рабочая версия

  • Автономная проверка

1. Подготовьте рабочую версию

  1. В GitHub Desktop выберите свой VariantNN-web. Откройте эту же папку в редакторе. Найдите form.html, form.js, скрипт каталога и sw.js. Проверьте имена по подключениям на ваших страницах.
  2. Для правок используйте локальный сайт. Откройте терминал в корне своего VariantNN-web и запустите python -B -m http.server 8000 --bind 127.0.0.1, если на компьютере доступен Python. Оставьте терминал открытым и перейдите по адресу http://localhost:8000/. Если уже работает локальный сервер редактора, используйте его адрес на localhost. На протяжении проверки сохраняйте прежний адрес, порт и профиль браузера. Если на этом компьютере через тот же адрес уже проверяли чужой проект, используйте другой свободный порт и затем сохраняйте его до конца работы.
  3. На главной отметьте номер версии, а в F12 → Application → Service Workers проверьте, что sw.js имеет состояние activated. Для первого запуска после регистрации один раз обновите страницу обычным Ctrl + R. В Cache Storage найдите кеш с номером вашей версии. Если использовали GitHub Pages, отдельно откройте опубликованный адрес через Settings → Pages → Visit site и запишите его версию.

Начальные условия

Service worker учебного проекта работает на GitHub Pages по HTTPS и на локальном сайте через localhost. Открытие index.html двойным щелчком даёт адрес file:// и для автономной проверки не подходит. Локальный и опубликованный адреса используют разные хранилища. На каждом адресе вводите свой запрос перед проверкой его восстановления.

2. Испытайте форму

На странице формы выберите позицию своего варианта. Сначала рассчитайте ожидаемый итог для количества 2 по своим исходным данным. Затем проведите испытания по порядку.

Действие Ожидаемый результат
Выберите позицию, введите 2 и нажмите кнопку расчёта На странице есть название позиции и верный итог. Адрес прежний
После удачного расчёта очистите количество и снова нажмите кнопку Браузер или приложение сообщает об ошибке. Предыдущий итог исчезает
Проверьте 0 и 1.5 по очереди Оба значения отклонены, новый итог не появляется
Верните 2 и снова выполните расчёт Форма снова показывает верный итог

Если после очистки поля остался старый итог, браузер мог отклонить ввод ещё до события submit. В таком случае код обработки отправки не успевает обновить сообщение. В form.js после объявления form и result добавьте обработчик изменения полей, если у вас его ещё нет:

JavaScript
form.addEventListener("input", function () {
  result.textContent = "";
});

Теперь итог очищается уже при редактировании, а следующий корректный расчёт заново заполнит #result. Повторите проверки после сохранения. Оставьте на месте встроенные ограничения из практики по форме и существующий вызов своей расчётной функции.

3. Проверьте восстановление поиска

  1. Откройте каталог. Введите запрос, по которому остаётся часть карточек. Запишите точный текст запроса и ожидаемое число карточек. Если в каталоге только одна карточка, используйте запрос с одним совпадением и отдельно запрос без совпадений.
  2. Нажмите Ctrl + R. Сверьте поле, карточки и счётчик, если он предусмотрен. Затем перейдите на главную и вернитесь в каталог по ссылке. Результат должен сохраниться и при таком переходе.
  3. Введите запрос без совпадений. Обновите страницу. Ожидается тот же запрос и пустая выдача. Очистите поле и ещё раз обновите страницу. Ожидается пустое поле и полный каталог.
  4. Если проверка не прошла, откройте F12 → Application → Local Storage и выберите адрес открытого сайта. Найдите ключ, который использует ваш скрипт. В учебном примере он называется catalog-search-v1. После ввода запроса в записи должен появиться новый текст, например {"query":"мини"}. Если записи нет, проверьте обработчик input, вызов сохранения и Console. Если запись верна, а выдача полная, проверьте порядок запуска: сначала прочитайте запрос, затем заполните поле и отрисуйте отфильтрованный список. Сверьте свой код с разбором восстановления интерфейса.

Два места хранения

В Cache Storage лежат страницы, скрипты и другие ресурсы. В Local Storage лежит значение запроса конкретного пользователя. Наличие catalog.html в кеше подтверждает сохранение файла, а восстановление поиска проверяется непосредственно в каталоге после перезагрузки.

4. Повторите сценарий без сети

  1. Если изменили файлы, которые входят в кеш, укажите следующий номер в VERSION в sw.js и такой же номер в видимой подписи на главной. Если добавили ресурс, используемый в основном сценарии, внесите его путь в FILES. Ключ поиска оставьте прежним, чтобы проверить сохранение старого запроса. На локальном адресе нажмите Update в панели Service Workers при выключенном Offline. Если новый worker ждёт активации, закройте все вкладки и окна приложения и снова откройте этот адрес. Сверьте видимую подпись с номером в Cache Storage.
  2. Введите в каталоге запрос с известным результатом. Откройте Application → Service Workers, выключите Bypass for network и Update on reload, включите Offline. Оставьте инструменты открытыми и нажмите обычное Ctrl + R. Каталог должен открыться заново с тем же полем и выдачей.
  3. Перейдите по ссылке на форму в этой же вкладке. Проверьте корректное количество и одно ошибочное. Ожидаются те же итог и отказ, что в проверке с доступной сетью. Снимите Offline после опыта.
  4. Если доступен телефон, повторите проверку на уже размещённой версии. Один раз откройте приложение по HTTPS с сетью и пройдите через каталог и форму. Введите запрос на самом телефоне. Затем закройте приложение, выключите Wi‑Fi и мобильные данные, откройте его с экрана телефона и повторите одно действие. В отчёте укажите номер проверенной версии и верните связь. Проверка в инструментах компьютера остаётся обязательной.
Что произошло Что проверить
Страница видна, пока она открыта, но пропадает по Ctrl + R в режиме Offline Зарегистрирован ли worker на текущем адресе и есть ли страница в кеше
Страница открывается без оформления или кнопка не работает В Network найдите не загрузившийся CSS или JS и сверьте имя и путь с FILES
После сохранения изменений видна старая версия Сверьте видимую подпись, VERSION и состояние waiting. Выполните шаг активации выше
Запрос пропал при переходе с компьютера на телефон или с localhost на Pages Введите запрос и повторите проверку на одном устройстве, адресе и в одном профиле

Если внешняя сеть недоступна, выполните шаги 1–3 на localhost. Если локальный сервер тоже недоступен, зафиксируйте успешные проверки формы и поиска на имеющемся рабочем адресе, причину остановки и отдельно результат автономной проверки, если его удалось получить на заранее открывавшейся версии.

5. Зафиксируйте результат

  • Запишите адрес и номер версии, ввод и ожидаемый итог формы, запрос и ожидаемое число карточек после перезагрузки. Для каждого испытания отметьте фактический результат или причину, по которой оно осталось невыполненным.
  • Если нашли дефект, укажите файл, правку и результат повторного испытания. Если исходное поведение прошло все проверки, сохраните свои исходные результаты для сравнения на защите.
  • Если меняли код, в GitHub Desktop → Changes проверьте состав правки и сделайте локальный коммит с описанием результата. Запишите его название. При наличии сети и размещённого сайта можно повторить опыт для опубликованной версии после её обновления.

Что показать преподавателю

На своём компьютере покажите восстановление запроса после перезагрузки в режиме Offline, затем проверьте форму на верном и ошибочном вводе. Назовите адрес и версию, на которых это проверили. Если шаг не прошёл, покажите сообщение браузера и последний подтверждённый результат. Эти проверки понадобятся на защите приложения.
