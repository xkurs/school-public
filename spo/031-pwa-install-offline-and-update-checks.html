Настройка PWA и проверка установки, автономной работы и обновления

На этой паре вы выпустите «Учебную версию 2». Продолжайте работу с сайтом, который вы разместили на первой паре. Проверки по ходу работы выполните самостоятельно. Преподавателя позовите один раз, в конце пары, чтобы показать версию 2 без интернета.

1. Откройте «Учебную версию 1»

  1. В GitHub Desktop выберите свой VariantNN-web в поле Current repository и нажмите Repository → View on GitHub. На GitHub откройте Settings → Pages → Visit site.
  2. На главной найдите надпись Учебная версия 1. Нажмите F12 → Application / Приложение → Service Workers. Если вкладка Application скрыта, нажмите » в верхней строке инструментов. Проверьте, что sw.js в состоянии activated, а галочка Offline снята. В Cache Storage найдите кеш с окончанием :v1.
  3. По ссылке на сайте откройте каталог. Введите свой поисковый запрос, при котором остаётся хотя бы одна карточка. Запомните запрос и число карточек. Нажмите Ctrl + R. Если поле и результат восстановились, после обновления вы сможете сравнить их с этой проверкой. Если поле уже сейчас пустое, зафиксируйте это и продолжайте с проверкой версии.
  4. Через меню Application → Manifest / Манифест проверьте название, значки и стартовую страницу. Если манифест ещё не готов, переходите к шагу 3. К проверке на телефоне можно вернуться после настройки по статье 29.

Если сайт ещё не размещён, вернитесь к шагу 5. Отправьте версию 1 и проверьте размещение в статье 30. Если номер рабочей версии уже менялся, используйте её текущий номер и следующий после него.

2. Самостоятельно проверьте запуск на телефоне

  1. Откройте на телефоне тот же HTTPS-адрес, который получили через Visit site. Убедитесь, что Wi‑Fi или мобильные данные включены. На главной проверьте надпись Учебная версия 1.
  2. В Chrome на Android откройте меню ⋮ и найдите «Добавить на главный экран» или «Установить приложение». На iPhone в Safari нажмите «Поделиться» и найдите действие добавления на экран «Домой». Подтвердите установку или добавление. На главном экране появится значок вашего приложения.
  3. Нажмите этот значок. Дождитесь загрузки главной, откройте каталог, затем форму. Вернитесь на главную. Телефон должен сначала открыть сайт с сетью, чтобы сохранить его файлы у себя.
  4. Закройте окно приложения. Выключите на телефоне и Wi‑Fi, и мобильные данные. Снова нажмите значок. Проверьте, что главная открылась, и перейдите в каталог. Выполните поиск или откройте форму и проверьте расчёт.
  5. Включите сеть обратно. Запомните, открылось ли приложение без сети и где оно запустилось при нажатии значка — в отдельном окне или во вкладке браузера.

Если телефон недоступен или в браузере нет нужной команды, сразу переходите к обновлению на компьютере.

3. Измените две строки и отправьте версию 2

Перед отправкой оставьте на компьютере две вкладки с вашим сайтом в одном профиле браузера. В первой откройте главную, во второй — каталог. В обеих пока работает версия 1.

  1. В редакторе откройте index.html. Найдите строку из первой пары и замените её на эту. Нажмите Ctrl + S.
HTML
<p>Учебная версия 2</p>
  1. В редакторе откройте sw.js. В первой строке замените "v1" на "v2" и сохраните файл. Список FILES и манифест оставьте прежними.
JavaScript
const VERSION = "v2";
  1. В GitHub Desktop → Changes поставьте галочки у index.html и sw.js. В поле Summary напишите Добавлена автономная версия 2. Нажмите Commit to main (или кнопку с именем вашей ветки), затем сверху нажмите Push origin.
  2. В GitHub откройте Actions и найдите запуск для коммита Добавлена автономная версия 2. Дождитесь зелёной галочки. Для проверки откройте в отдельной вкладке HTTPS-адрес сайта с sw.js в конце, например https://логин.github.io/репозиторий/sw.js. Если в первой строке стоит "v2", GitHub Pages отдаёт новый скрипт.

Что должно получиться. На GitHub есть коммит с двумя файлами, а по адресу sw.js открыт код версии 2. Ваши открытые страницы пока могут показывать версию 1.

4. Посмотрите, как браузер переключается на версию 2

  1. Вернитесь во вкладку с главной. Вторая вкладка с каталогом пока открыта. Нажмите F12 → Application → Service Workers. Проверьте, что Offline, Update on reload и Bypass for network выключены. Нажмите ссылку Update рядом с регистрацией sw.js. Если ссылки нет, нажмите Ctrl + R.
  2. Подождите, пока рядом с новым скриптом появится waiting to activate. Это означает, что браузер уже подготовил новые файлы и ждёт закрытия старых вкладок. Откройте Cache Storage и найдите кеш с окончанием :v2. Пока вторая вкладка открыта, обычная перезагрузка главной может по-прежнему показать Учебная версия 1.
  3. Закройте все вкладки с приложением на этом компьютере, включая вкладку с файлом sw.js. Если открыто отдельное окно установленного приложения, закройте и его. Через несколько секунд снова откройте сайт по прежнему HTTPS-адресу из Visit site.
  4. На главной проверьте надпись Учебная версия 2. В Application → Cache Storage должен быть кеш с окончанием :v2. Откройте каталог и проверьте, сохранились ли запрос и число карточек из шага 1.

Если новая версия не появляется, сначала проверьте зелёную галочку в Actions и строку версии в опубликованном sw.js. Если в панели Service Workers по-прежнему видно waiting to activate, проверьте вкладки и окна браузера. Если новый скрипт не установился, откройте Console / Консоль и сверьте адрес файла из ошибки со списком FILES. Для этого опыта оставьте данные сайта и регистрацию на месте.

5. Один показ преподавателю в конце пары

Позовите преподавателя к своему компьютеру. Оставьте открытой вкладку со своим приложением на GitHub Pages и инструменты разработчика (F12).

  1. На главной откройте Application → Service Workers. Поставьте галочку Offline и нажмите Ctrl + R. Покажите, что на странице появилась надпись Учебная версия 2.
  2. В той же вкладке покажите одно действие: поиск в каталоге или расчёт в форме. Затем снимите галочку Offline, чтобы вернуть сеть.

Если к концу пары версия 2 ещё не открывается, покажите последний выполненный шаг и сообщение браузера или GitHub во время этого же показа.
