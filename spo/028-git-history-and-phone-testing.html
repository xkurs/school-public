Установка Git и первые коммиты своего веб-проекта

Сегодня работаем за компьютером с уже созданным VariantNN-web. Научимся сохранять историю файлов: сначала зафиксируем имеющийся проект, затем уточним его заголовок и сохраним отдельное изменение. Новый вариант и новый веб-проект создавать не нужно.

Результат: вы находите свою папку, запускаете в ней Git Bash, видите версию Git, создаёте локальный репозиторий и можете показать два коммита и различие между ними. Если история уже есть, сохраняйте её: первый коммит заново не создают.

Git и GitHub — разные вещи

Git — программа, которая сохраняет историю выбранных файлов на вашем компьютере. Репозиторий — проект с такой историей. Коммит — сохранённый снимок выбранных изменений с сообщением. GitHub — интернет-сервис для размещения репозиториев. Команда git commit ничего не отправляет на GitHub. На следующей паре, тоже за компьютерами, подключим готовый репозиторий к GitHub через GitHub Desktop, а при готовности продолжим размещением сайта и подготовкой PWA без собственного сервера.

1. Найдите свою папку проекта

Нажмите Win + E: откроется Проводник Windows. Найдите папку своего прежнего проекта VariantNN-web, где NN — ваш номер, например Variant07-web. Откройте её двойным щелчком. Внутри должны быть собственные HTML-файлы, CSS и JavaScript. Не выбирайте папку всей группы или папку с несколькими вариантами.

Откройте index.html в привычном редакторе и убедитесь, что это ваш проект. Сохраните открытые файлы сочетанием Ctrl + S. Git читает содержимое с диска; несохранённый текст редактора он не увидит.

Пример знакомого состава проекта:

Файл Что в нём находится
index.html Главная страница
catalog.html Страница каталога
form.html Страница формы
style.css Оформление
catalog.js Прежние данные и упражнения JavaScript
catalog-page.js Вывод и поиск на странице каталога
form.js Обработка формы

Это ориентир, а не требование создать отсутствующие файлы. catalog.js и catalog-page.js могут выполнять разные задачи: не заменяйте один другим. Сохраняйте свои изображения и остальные реальные файлы. Сегодня не требуется достраивать функции из предыдущих занятий: первый снимок может честно фиксировать промежуточный результат.

2. Установите Git, если его ещё нет

Откройте меню «Пуск» и введите Git Bash. Если приложение находится, переходите к следующему разделу: сначала проверим его работу командой git --version.

Если Git Bash отсутствует, сообщите преподавателю. Установку на учебном компьютере выполняют только при разрешении, действующем в аудитории; если нужны права администратора, их предоставляет ответственный сотрудник.

  1. Откройте официальную страницу установки Git для Windows.
  2. Выберите установщик для архитектуры компьютера. На обычном компьютере Windows x64 нужен вариант x64; если тип системы неизвестен, уточните у преподавателя.
  3. Запустите скачанный установщик Git for Windows. Он устанавливает Git и Git Bash — отдельно искать Bash не нужно.
  4. На шаге выбора редактора Git можно выбрать знакомый редактор из списка, например Visual Studio Code, если он установлен. Если знакомого варианта нет, оставьте предложенный: в этой статье сообщение коммита задаётся прямо командой commit -m, поэтому отдельный редактор не откроется. Устанавливать ещё один редактор для первого упражнения не требуется.
  5. На остальных шагах оставляйте предложенные установщиком рекомендуемые значения. Не меняйте сетевые, системные и экспериментальные параметры ради этого задания.
  6. Завершите установку. Закройте ранее открытые терминалы и откройте Git Bash заново: старое окно может не увидеть установленную программу. При необходимости закройте и снова откройте Проводник.

Если установка запрещена или не завершилась, переходите к резерву вместе с преподавателем. Наличие работающего Git проверяется командой, а не только появлением значка.

3. Откройте именно Git Bash в папке проекта

В Проводнике откройте VariantNN-web. Щёлкните правой кнопкой по свободному месту внутри папки, а не по HTML-файлу. Выберите Open Git Bash here / Git Bash Here. В Windows 11 сначала может потребоваться пункт «Показать дополнительные параметры».

Если пункта нет, найдите Git Bash через «Пуск» и откройте его. В Проводнике щёлкните по адресной строке и скопируйте полный путь своей папки. В Git Bash перейдите туда командой cd, заключив путь в кавычки. Для условного пути D:\Study\Variant07-web команда выглядит так:

Bash
cd "D:/Study/Variant07-web"

Замените пример своим реальным путём; буква диска и папки могут отличаться. В этой записи используйте прямые косые черты /. Кавычки нужны в том числе для пути с пробелами. Команда при успехе обычно ничего не печатает.

Как читать терминал

Окно показывает приглашение, например student@PC MINGW64 /d/Study/Variant07-web, а ниже знак $. Это приглашение программы к вводу. Не копируйте приглашение, знак $, слово bash и рамку блока. Вводите только строку команды. Выполняйте по одной команде, нажимайте Enter и читайте ответ. Вставить скопированную строку в Git Bash обычно можно через Shift + Insert или пункт Paste контекстного меню.

Все команды статьи предназначены для Git Bash. Не переключайтесь между ним, PowerShell и командной строкой Windows.

4. Проверьте Git и текущую папку

Введите:

Bash
git --version

Ожидаемый ответ начинается с git version, например git version 2.x.y.windows.1. Числа могут быть другими. Если получено command not found, не вводите остальные команды Git до устранения ошибки по таблице в конце статьи.

Теперь узнайте текущую папку:

Bash
pwd

Ожидается путь к вашему VariantNN-web. В Git Bash диск D: может отображаться как /d/, а C: — как /c/. Это нормальная запись пути.

Посмотрите файлы:

Bash
ls

В ответе должны быть знакомые имена: например, index.html, style.css и остальные файлы проекта. Если вы видите рабочий стол, чужие варианты или другую папку, вернитесь в Проводник и откройте Git Bash в правильном месте. Не создавайте репозиторий, пока путь не проверен.

5. Проверьте, есть ли история, и создайте её при необходимости

Введите:

Bash
git rev-parse --show-toplevel

Эта команда показывает корневую папку существующего репозитория. Прочитайте ответ до следующего действия:

Ответ Что делать
Путь заканчивается именно вашим VariantNN-web Репозиторий уже есть. Пропустите git init, сохраните прежнюю историю и переходите к настройке автора
fatal: not a git repository (or any of the parent directories): .git До создания истории это ожидаемый ответ: Git пока не нашёл репозиторий. Если pwd и ls подтвердили свою папку, выполните git init ниже
Выведена родительская или другая папка Остановитесь и покажите путь преподавателю. Ваша папка оказалась внутри другого репозитория; добавление файлов сейчас может затронуть чужой проект

Только для проверенной папки без существующей истории выполните:

Bash
git init

Ожидается сообщение Initialized empty Git repository in .../VariantNN-web/.git/. Git создал внутри проекта служебную папку .git; реальные HTML, CSS, JavaScript и изображения остались на месте. Не открывайте и не редактируйте внутренние файлы .git.

Снова проверьте корень:

Bash
git rev-parse --show-toplevel

Теперь ожидается путь именно к VariantNN-web. Если ответ отличается, остановитесь и покажите его преподавателю.

Имя ветки

В выводе может появиться main или master. Сейчас это имя текущей ветки истории. Для первых локальных коммитов подойдут оба варианта; переименовывать ветку ради совпадения со скриншотом не требуется.

6. Задайте учебную подпись автора только для этого проекта

Коммит содержит имя и электронный адрес автора. Это подпись в истории, а не вход в GitHub: пароль и код подтверждения здесь не вводят.

Для первого локального упражнения используйте согласованное учебное обозначение без настоящих персональных данных. Например, для варианта 07:

Bash
git config --local user.name "Student-07"

При успехе ответ обычно пустой. Впишите свой номер вместо 07.

Bash
git config --local user.email "student-07@example.invalid"

Это намеренно учебный, недействующий адрес, а не почтовый ящик. Подставьте тот же номер. Параметр --local ограничивает настройку этим репозиторием и не меняет подпись остальных пользователей компьютера.

Проверьте имя:

Bash
git config --local user.name

Ожидается введённое обозначение, например Student-07.

Проверьте адрес:

Bash
git config --local user.email

Ожидается введённый учебный адрес.

Подпись для будущего GitHub

Перед отправкой репозитория на следующей паре проверьте подпись. При наличии GitHub можно использовать личный адрес noreply, скопированный из настроек электронной почты своей учётной записи. Не придумывайте его по чужому примеру. Новая настройка влияет на будущие коммиты: подписи уже созданных коммитов автоматически не меняются. Поэтому настоящую личную почту в учебный пример не вводим.

7. Посмотрите состояние и выберите файлы первого коммита

Введите:

Bash
git status

В новом репозитории ожидаются No commits yet и список Untracked files. Это означает: история пока пустая, файлы есть, но Git ещё не включил их в отслеживание.

Сообщение status Простыми словами
Untracked files Новый файл ещё не выбран для истории
Changes not staged for commit Отслеживаемый файл изменён, но новая правка ещё не выбрана
Changes to be committed Эти изменения выбраны для ближайшего коммита
nothing to commit, working tree clean Среди отслеживаемых файлов нет новых изменений для коммита

Между файлом на диске и коммитом есть область подготовки. Команда git add помещает туда текущее содержимое выбранного файла. Она ничего не отправляет в интернет.

Добавляйте файлы по известным именам. Например, если index.html действительно есть:

Bash
git add index.html

Ожидаемый ответ при успехе пустой. Так же добавьте каждый существующий файл своего приложения. Следующие команды выполняйте только для файлов, которые есть у вас:

Bash
git add catalog.html
Bash
git add form.html
Bash
git add style.css
Bash
git add catalog.js
Bash
git add catalog-page.js
Bash
git add form.js

Успешное добавление обычно не печатает сообщений. Если какого-то файла нет, пропустите соответствующую команду; не создавайте пустой файл ради списка.

Изображения тоже нужны проекту. Посмотрите их реальные имена в Проводнике. Например, только если у вас действительно существует файл images/logo.png, добавьте его так:

Bash
git add "images/logo.png"

Для другого изображения подставьте его фактический путь, например своё имя JPG или SVG. Кавычки обязательны, если есть пробелы. Повторите для используемых изображений и других нужных файлов проекта. Не добавляйте личные документы, пароли, токены и чужие работы. Не применяйте git add . наугад: сначала надо понимать состав выбранных файлов.

Посмотрите результат:

Bash
git status

Теперь выбранные файлы должны быть в разделе Changes to be committed. Проверьте, что в списке именно ваша работа.

Посмотрите содержимое будущего коммита:

Bash
git diff --cached

Для новых текстовых файлов видны строки с +: это добавляемое содержимое. Для изображения Git обычно сообщает о различии двоичных файлов, а не показывает картинку. Если открылся просмотрщик на весь экран, листайте стрелками; для выхода нажмите латинскую q.

Сохранить → выбрать → зафиксировать

Ctrl + S сохраняет файл на диск. git add имя-файла выбирает его текущее содержимое. git commit создаёт снимок выбранного. Если после add вы снова изменили файл, сохраните его и повторите add, чтобы новая правка тоже вошла в коммит.

Если выбран непонятный или чужой файл, покажите список преподавателю до коммита. Для точного удаления ошибочно выбранного нового файла из подготовки преподаватель может применить git rm --cached -- "имя-файла": файл остаётся на диске. Не заменяйте эту команду обычным git rm, который удаляет рабочий файл.

8. Создайте первый коммит и прочитайте историю

После проверки подготовленного содержимого выполните:

Bash
git commit -m "Сохранено текущее состояние веб-проекта"

Ожидается сообщение с именем ветки, коротким идентификатором и текстом коммита; для первого снимка может быть пометка root-commit. Ниже Git перечислит количество изменённых файлов. Значения зависят от вашего проекта. Параметр -m задаёт сообщение сразу, поэтому отдельный редактор для сообщения не открывается.

Проверьте состояние:

Bash
git status

Если все нужные файлы включены и после этого не менялись, ожидается nothing to commit, working tree clean. Если остались файлы в списке, прочитайте их имена: возможно, нужное изображение ещё не добавлено. Не скрывайте остаток и не удаляйте его ради чистого вывода.

Посмотрите историю:

Bash
git log --oneline -5

Пример строки: a1b2c3d Сохранено текущее состояние веб-проекта. У вас будет свой идентификатор. Это короткий хеш, по которому можно найти конкретный коммит. Самый свежий коммит находится сверху.

Если репозиторий существовал раньше и status сразу показывает чистое состояние, пустой первый коммит не нужен. Найдите имеющееся сохранённое состояние через log, запишите его хеш и продолжайте маленькой правкой ниже. Если есть прежние незавершённые изменения, сначала разберите их с преподавателем; не добавляйте всё разом ради выполнения команды.

9. Уточните заголовок и сохраните второй коммит

Сделайте одну полезную и понятную правку в своём проекте. Откройте index.html в редакторе и найдите видимый заголовок <h1>. Уточните его так, чтобы он лучше объяснял назначение именно вашего приложения. Например, вместо общего «Мой сайт» напишите осмысленное название своего каталога. Не копируйте чужую тематику. Если название уже хорошее, согласуйте небольшое уточнение пояснения рядом с ним.

Сохраните файл (Ctrl + S). Откройте главную страницу привычным способом в браузере и обновите её. Убедитесь, что виден новый текст. Для этой проверки достаточно своего компьютера и существующего проекта.

Вернитесь в Git Bash:

Bash
git status

Ожидается modified: index.html в разделе Changes not staged for commit.

Посмотрите, что поменялось после первого коммита:

Bash
git diff -- index.html

Строка с - — прежний текст, строка с + — новый. Заголовки сравнения --- и +++ обозначают файлы. Проверьте, что кроме задуманного текста ничего случайно не изменено.

Выберите сохранённую правку:

Bash
git add index.html

При успехе ответ пустой. Прочитайте подготовленное сравнение:

Bash
git diff --cached -- index.html

Ожидается та самая правка заголовка. Обычный git diff показывает ещё не подготовленные изменения, а git diff --cached — выбранные для следующего коммита.

Создайте второй коммит:

Bash
git commit -m "Уточнён заголовок главной страницы"

Ожидается новый хеш и сообщение об изменении index.html. Если вы уточняли пояснение, напишите соответствующее сообщение вместо сообщения о заголовке.

Прочитайте историю:

Bash
git log --oneline -5

В новом репозитории теперь две строки: новая правка сверху и исходное состояние ниже. Для просмотра последнего коммита выполните:

Bash
git show HEAD -- index.html

HEAD здесь обозначает текущий коммит. Ожидается его сообщение и сравнение старого и нового текста. Для выхода из просмотрщика нажмите q.

В конце проверьте:

Bash
git status

Ожидается чистое состояние, если других изменений нет. История остаётся только на этом компьютере. Коммит не создаёт сетевую копию и не защищает от потери всей папки или диска. Сохраните проект привычным разрешённым способом вместе со скрытой папкой .git; не удаляйте её и не переносите только HTML без истории.

Если команда не сработала

Не вводите весь набор команд повторно. Прочитайте последнюю ошибку и найдите соответствующий случай.

Что видно Причина и точное следующее действие
git: command not found В этом окне Git не найден. Закройте терминал, откройте Git Bash заново и выполните git --version. Если Git Bash отсутствует или ошибка остаётся, вернитесь к разрешённой установке с преподавателем; остальные команды пока не вводите
not a git repository до init Нормальный ответ при первом запуске. Проверьте pwd и ls; только в своём VariantNN-web выполните git init
not a git repository при status или add после успешного init Скорее всего, открыта другая папка или другое окно. Откройте Git Bash Here в прежнем VariantNN-web, проверьте pwd и git rev-parse --show-toplevel. Не выполняйте новый init в случайной папке
pathspec ... did not match any files Git не нашёл написанное имя. Выполните ls, проверьте расширение, путь и регистр; для файла в подпапке укажите весь относительный путь в кавычках. В Проводнике включите отображение расширений, если файл мог называться index.html.txt. Повторите git add только с существующим именем
Author identity unknown или Please tell me who you are В своём репозитории выполните две команды git config --local из раздела 6, проверьте их выводом и повторите git commit -m .... Подготовленные изменения обычно сохраняются: создавать проект заново не надо

Минимум для завершения пары

Покажите преподавателю свой проект и команды, а не только переписанный текст статьи:

  1. git --version отвечает версией; pwd и git rev-parse --show-toplevel указывают на свой проект.
  2. В истории есть исходное состояние и отдельная небольшая правка с понятными сообщениями; если история уже была, она сохранена.
  3. git show HEAD -- index.html показывает именно вашу правку. Вы можете найти её в редакторе и браузере.
  4. git status соответствует вашему объяснению: нужные изменения закоммичены, оставшиеся файлы названы отдельно.
  5. Вы объясняете разницу между сохранением файла, add, коммитом и отправкой на GitHub.

Запишите в тетрадь путь к проекту и два коротких хеша с сообщениями. Рабочую папку с .git сохраните для следующей пары.

Проверьте понимание

- Почему до git init сообщение not a git repository может быть ожидаемым? - Почему перед init нужно прочитать путь папки? - Что произойдёт, если после сохранения HTML забыть выполнить git add? - Чем различаются git diff и git diff --cached? - Появился ли проект на GitHub после git commit? Где сейчас находится история?

Если закончили раньше

Прочитайте старый коммит, подставив его настоящий короткий хеш из log в команду git show ХЕШ -- index.html. Она только показывает историю и не меняет рабочие файлы. Сравните её с git show HEAD -- index.html и объясните, какое состояние было сохранено раньше.

Затем можно осмысленно уточнить одно описание на главной странице и самостоятельно повторить цикл: сохранить → просмотреть diff → выбрать файл → просмотреть diff --cached → сделать коммит → прочитать историю. Не меняйте ради количества коммитов случайные символы и не переходите вперёд к новым инструментам.
