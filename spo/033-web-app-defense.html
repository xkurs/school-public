Защита веб-приложения: самостоятельное изменение проекта и объяснение кода

Откройте копию своего VariantNN-web, которую получили с GitHub на первой паре. На экзамене вы получите конкретное условие и адаптируете под него своё приложение. Сегодня выполните небольшое изменение по тому же маршруту: правка, локальная проверка, отправка и показ результата.

Что показать преподавателю

В конце второй пары откройте подготовленные вкладки и выполните три коротких действия при преподавателе:

  1. Локальный сервер. Покажите изменённый товар в каталоге и форме. Назовите цену и ожидаемую стоимость двух единиц. Введите 2, затем 0. Преподаватель увидит верный итог, затем отказ и отсутствие старого итога.
  2. GitHub и GitHub Pages. Покажите последний коммит в своём репозитории и откройте из настроек Pages опубликованный адрес. Преподаватель увидит новую метку версии, изменённую карточку с изображением и рабочие переходы из меню.
  3. Телефон. При выключенных Wi‑Fi и мобильных данных откройте приложение с экрана телефона. Перейдите в каталог, найдите изменённый товар по подготовленному запросу и обновите страницу. Преподаватель увидит тот же запрос и выдачу после обновления.

Покажите в редакторе, какие данные поменяли и откуда форма берёт цену. Запишите адрес репозитория, адрес Pages, версию приложения и короткий результат каждого испытания.

Выполните пробное задание

Представьте, что ваш проект заказал магазин настольных игр. Для репетиции замените одну позицию в своём каталоге на «Космические шахматы» с ценой 1200 ₽. Если преподаватель дал другой товар и цену, используйте его условие. Остальные позиции оставьте для проверки, что поиск по-прежнему может отбирать часть каталога.

  1. Найдите файл с данными, из которых строится каталог. Измените название, цену и описание выбранной позиции. Для учебного товара можно взять своё изображение или подходящий файл из папки проекта. Если каталог пока выводит карточки без изображений, добавьте объекту товара свойство image с относительным путём. Внутри цикла renderCatalog, после сборки карточки, но до её добавления в каталог, вставьте:

javascript if (item.image) { const photo = document.createElement("img"); photo.src = item.image; photo.alt = item.name; card.append(photo); }

Имена item и card взяты из разбора отрисовки каталога. Сверьте их со своим кодом. 2. Откройте форму и обновите подпись того же товара. Если форма берёт цену из общего файла данных, проверьте, что она получила новую цену. Если форма всё ещё передаёт в getResult одинаковые unitValue и extraValue для всех позиций, найдите value изменённого пункта option. Для этого пункта передавайте в getResult новую цену и нулевую добавку, для остальных сохраните прежние аргументы. Сверьте чтение выбранной позиции и вызов функции с разбором формы. Проверьте, что итог для учебного товара подписан в рублях, если ваш исходный проект использовал другие единицы. 3. Подберите короткий запрос, который оставляет изменённый товар, например шахматы. Проверьте, что по нему действительно виден нужный товар и что при очистке поля видны остальные позиции. 4. Подготовьте номер новой версии на главной и в VERSION в sw.js. Если добавили или заменили путь к ресурсу, сверьте список FILES. Помощь по недостающим частям есть в таблице первой пары.

Локальный сервер — расчёт и ошибки

  1. Откройте проект на том же локальном адресе, что на первой паре. Сверьте изменённое название и цену в каталоге и в выборе товара на форме. При старой версии проверьте папку сервера и настройки локальной проверки.
  2. Выберите изменённый товар, введите 2 и выполните расчёт. Для «Космических шахмат» по 1200 ₽ ожидаются название товара и итог 2400 ₽. Для своего условия вычислите итог заранее.
  3. Введите 0 и попробуйте снова. Прежний итог должен исчезнуть, форма должна отклонить количество. Если она пропускает ошибку или показывает старое сообщение, повторите проверку формы и очистки результата.

GitHub — исходники и версия сайта

  1. В GitHub Desktop откройте Changes и проверьте, что в коммит попадут только файлы работы, включая новый ресурс, если он появился. Сделайте коммит с понятным сообщением и нажмите Push origin. Если нужно, следуйте инструкции по отправке.
  2. Откройте репозиторий на GitHub. Найдите последний коммит в той ветке, из которой размещается Pages. Покажите в коммите изменённые исходники и проверьте, что ресурс карточки присутствует в репозитории.
  3. Дождитесь успешного размещения в Actions, затем откройте сайт через Settings → Pages. Сверьте метку новой версии на главной. Перейдите по меню в каталог и форму. В каталоге найдите изменённую карточку и убедитесь, что загрузилось её изображение. Если путь работает локально, а на Pages изображение отсутствует, проверьте, есть ли файл в опубликованной ветке и совпадает ли регистр букв. Используйте относительные пути, как в инструкции по размещению.
  4. Если размещение прошло, а видна предыдущая версия, проверьте активацию по инструкции по обновлению PWA. Повторно откройте Pages и предъявите именно версию с вашей правкой.

Телефон — запуск и поиск без сети

  1. С включённой связью откройте тот же адрес Pages на телефоне. Установите приложение или добавьте его на главный экран по инструкции пары 29. Запустите его с экрана, проверьте метку новой версии, откройте каталог и один раз обновите страницу с сетью, чтобы приложение успело подготовить автономную копию.
  2. Закройте приложение, выключите Wi‑Fi и мобильные данные. Заново запустите приложение с экрана и перейдите из главной в каталог. Проверьте, что на узком экране можно пользоваться меню и поиском.
  3. Уже без сети введите подготовленный запрос. Сверьте выдачу, затем обновите страницу обычным способом. Если в установленном приложении нет команды обновления, закройте его, запустите снова и вновь перейдите в каталог. Поле и выдача должны восстановиться. Очистите запрос и убедитесь, что снова виден весь каталог. После проверки верните связь.
  4. Если сайт без сети не открылся, проверьте, что телефон открывал новую версию с сетью и что service worker сохраняет HTML, стили, скрипты и ресурсы карточек. Вернитесь к списку ресурсов для кеша. Если каталог открылся, а запрос исчез, проверьте сохранение запроса и порядок восстановления выдачи.

Если часть проверок недоступна

  • При недоступном GitHub покажите локальный коммит и работающий сценарий формы. Отдельно запишите, какие шаги требуют сети: скачивание, отправка или проверка Pages.
  • Если телефон недоступен или Pages ещё не развернулся, можно проверить автономный каталог на доступном адресе через F12 → Application → Service Workers → Offline. Сначала выключите Bypass for network, загрузите каталог с сетью и убедитесь, что worker новой версии активен. После опыта снимите Offline. Отметьте, что запуск на реальном телефоне остался для повторной проверки.
  • Если проект открылся, но какой-то шаг сломался, назовите ожидаемый результат, покажите фактический и запишите, какой файл или настройку нужно проверить.
