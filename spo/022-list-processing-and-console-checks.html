Обработка списка записей и проверка функций в консоли

Сегодня лекция с демонстрацией: разберём, как программа обрабатывает не одну запись, а весь список карточек. Работаем со своим catalog.js из пары 21; результат по-прежнему виден в консоли, страницу пока не меняем.

Что должно получиться: на своём массиве catalog вы умеете получать список названий, отбирать записи по условию, находить одну запись и проверять результат отдельной функцией. Данные карточек и расчёт пары 20 сохраняются.

Рабочий ритм: изменить → сохранить → обновить страницу → проверить консоль.

1. Проверьте исходное состояние

Откройте свою папку VariantNN-web. В index.html должно остаться одно подключение программы — catalog.js. В консоли (F12 → Console / Консоль) после обновления страницы видны три блока карточек и расчёт выбранной записи.

Сделайте: убедитесь, что в catalog.js есть массив catalog из трёх объектов и работающая функция getResult. Если расчёт пропал, восстановите его по паре 20 до продолжения.

Проверьте: catalog.length в консоли даёт 3, а catalog[0].name — название первой карточки.

Если в вашем варианте карточек другое число, работайте со своим количеством: все действия ниже не зависят от трёх.

2. Список записей — это обычный массив

Массив хранит значения по порядку, и каждая его запись — объект с полями position, name, specs, description. Пока массив небольшой, его можно проверить глазами.

Опыт в консоли:

JavaScript
console.table(catalog);
console.log(catalog.length);

console.table выводит массив объектов таблицей: столбцы — свойства, строки — записи. В консоли браузера таблицу можно развернуть и отсортировать по столбцу.

Проверьте: в таблице три строки, столбцы совпадают с именами свойств, а length равно числу записей.

Таблица помогает заметить пропущенное свойство или лишнюю запись. Это проверка данных, а не вывод для пользователя: пользователь таблицу не увидит.

3. Получите список названий: map

Представьте, что из списка записей нужны только названия — например, чтобы заполнить список выбора в форме. Для этого есть метод массива map: он создаёт новый массив, где каждому элементу соответствует результат действия.

JavaScript
const names = catalog.map(item => item.name);
console.log(names);

Запись item => item.name — короткая функция: «для каждой записи item взять её name». Стрелка => отделяет параметр от результата. То же действие полной записью (это отдельный пример, не добавляйте его рядом с коротким):

JavaScript
const namesFull = catalog.map(function (item) {
  return item.name;
});

Оба варианта делают одно и то же. Исходный catalog не меняется: map возвращает новый массив.

Сделайте: получите в консоли массив названий своих карточек и его длину.

Проверьте: names.length совпадает с catalog.length, а порядок названий совпадает с порядком карточек.

Ошибка item.name is not a function означает лишние скобки после name; undefined в массиве — опечатку в имени свойства.

4. Отберите записи по условию: filter

filter тоже создаёт новый массив, но оставляет только те элементы, для которых условие истинно.

JavaScript
const longNames = catalog.filter(item => item.name.length > 8);
console.log(longNames.length);

Условие item.name.length > 8 проверяется для каждой записи. Записи, где условие ложно, в результат не попадают. Пустой результат — это пустой массив [], а не undefined.

Сделайте: отберите записи, в названии которых есть слово из вашей предметной области (например, часть названия первой карточки). Выведите число найденных и их названия.

Проверьте: при изменении условия число найденных записей меняется; исходный catalog остаётся прежним.

5. Найдите одну запись: find

find возвращает первую запись, подходящую под условие, или undefined, если подходящих нет.

JavaScript
const selectedName = "Название вашей карточки";
const found = catalog.find(item => item.name === selectedName);
console.log(found);

=== сравнивает значения, = присваивает. Сравнение названий чувствительно к регистру и пробелам: "Набор" и "набор" — разные строки.

Сделайте: найдите свою карточку по точному названию, выведите её характеристику и описание. Затем измените selectedName на название с другой буквой и посмотрите результат.

Проверьте: при точном совпадении выводится объект, при неточном — undefined. Попытка сразу прочитать found.name у undefined даёт ошибку TypeError: сначала проверяют, что запись найдена.

JavaScript
if (found) {
  console.log(found.specs);
} else {
  console.log("Запись не найдена");
}

6. Оформите обработку списка отдельной функцией

Теперь соберём знакомые действия в функцию, которая принимает массив и строку запроса, а возвращает массив подходящих записей.

JavaScript
function filterByText(items, query) {
  const normalized = query.trim().toLowerCase();
  if (normalized === "") {
    return items;
  }
  return items.filter(item => item.name.toLowerCase().includes(normalized));
}

Разберём по частям:

Запись Что делает
items параметр-массив: любая коллекция записей
query параметр-строка: то, что ввёл пользователь
trim() убирает пробелы по краям
toLowerCase() приводит к нижнему регистру, чтобы «Набор» и «набор» совпадали
includes(...) проверяет, есть ли часть строки внутри названия
return отдаёт результат и завершает функцию

Пустой запрос возвращает все записи — это удобно для формы поиска: пользователь ещё ничего не ввёл, а список уже показан.

Сделайте: добавьте функцию в catalog.js после массива (до или после getResult — на ваш выбор, но не внутри другой функции). Проверьте её в консоли:

JavaScript
console.log(filterByText(catalog, "").length);
console.log(filterByText(catalog, "часть названия"));
console.log(filterByText(catalog, "  ЧАСТЬ  ").length);
console.log(filterByText(catalog, "нет такой записи"));

Проверьте: пустой запрос — все записи; часть названия — нужные; другой регистр и лишние пробелы не мешают; несуществующий текст — 0, а не ошибка.

filterByText(...).length считает найденные записи. Если консоль показывает undefined, функция ничего не вернула: проверьте return.

7. Прогоните свои испытания

Выполняйте по одному опыту: сохранить файл, обновить страницу, прочитать вывод, вернуть исходные данные.

Опыт Что изменить Что должно произойти
Полный список Пустой запрос Возвращаются все записи, счётчик равен catalog.length
Часть названия Взять 3–4 буквы из начала названия Найдена хотя бы одна запись, лишних нет
Другой регистр Записать запрос заглавными буквами Результат тот же
Пробелы Добавить пробелы до и после запроса Результат не меняется
Нет совпадений Ввести текст, которого нет в названиях Пустой массив, счётчик 0, ошибки нет
Другое свойство Сравнить по specs вместо name Поиск идёт по характеристике; объясните, где это уместно

После опыта с specs верните поиск по названию: в следующей паре поиск будет связан с полем ввода.

Покажите результат

Покажите таблицу catalog, массив названий, результат filterByText для трёх запросов и найденную запись. Объясните, чем map, filter и find отличаются по результату: новый массив, отобранный массив, одна запись или undefined.

Отдельный отчёт не нужен: достаточно открытого catalog.js и выполненного опыта по выбору преподавателя.

Если закончили раньше

  1. Получите названия в обратном порядке: catalog.map(item => item.name).reverse().
  2. Посчитайте, сколько записей содержит слово из вашей предметной области: filterByText(catalog, "слово").length.
  3. Напишите findByPosition(items, position), которая находит запись по исходному номеру position. Проверьте номер, которого нет.

Объясните, почему для поиска по номеру удобнее find, а не filter.
